# StopWatch v1.0 实机验收记录 — 2026-11-05

本次针对一台 M5Stack StopWatch v1.0，验证显示、触摸、两颗可编程按键和震动。
按用户要求没有备份原厂固件；首次写入匹配 ESP32-S3 的完整镜像，后续修正写入
0x10000 应用分区。esptool 写入后哈希校验通过。

## 设备与测试方式

- ESP32-S3 QFN56，芯片修订 v0.2，16 MiB Flash，8 MiB PSRAM。
- 原生 USB Serial/JTAG；USB hello 与有 requestId 关联的诊断回复确认身份。
- 固件 0.1.1-stopwatch-dev，沿用 ESP-IDF、esp_lcd、自研 RGB565、LVGL 字体和 JSONL。
- 软件读取 SPI 提交、GPIO/IOE、触摸坐标和输入计数；用户确认实际画面、跟手、
  会话/亮度变化与触觉。软件 ACK 或 GPIO 锁存状态不单独作为物理成功证据。
- 本地原始记录在 artifacts/stopwatch/hil/，不随源码发布。

## 结果

| 项目 | 自动记录 | 人工确认 | 结果 |
| --- | --- | --- | --- |
| 显示 | 连续提交 3936 帧，display.error=0 | 红绿蓝三栏、白色圆框正常；宠物/会话可见 | 通过 |
| 触摸 | CST820B ID=0xB7，固件=2；最终轮 6 次触摸、2 次滑动 | 中心/四周十字跟手；左右滑动分别切换下一/上一会话 | 通过 |

| 蓝色键 | 短按 3 次、长按 1 次；上报 button.sw2.short_press | 会话切换和调暗正常 | 通过 |

最终轮持续约 8 分半，设备 boot ID 保持一致，显示没有返回错误。
3 个合成测试会话保持有效，手动选择在定期快照中保留。短时观察不代表 24 小时
稳定性或电池续航验收。停止控制台后已清除合成会话，恢复宠物界面。

## 发现和修复

1. 初次运行 USB 应用已在线，但用户确认黑屏。补齐 IOE 推挽/上下拉配置和显式
   开屏后，三色栏及边框恢复正常；未将单纯的 SPI DMA 完成当作显示通过。
2. 初版触摸仅做一次地址 probe，曾出现同一硬件不同启动后 touch 能力不同。
   现在在屏幕初始化后重新复位触摸，通过寄存器读取识别并有界重试；读取到
   CST820B ID 0xB7 / 固件 2，并完成实际点按和滑动。
3. 主循环旧帧时间戳可能早于刚收到的消息。无符号时间相减导致新会话被误判
   超时，按键虽被解码却没有会话可切换。刷新处理时间，并为会话/在线判断增加
   向前时间检查。新增回归在旧代码上重现失败、修正后通过；实机确认会话稳定。
4. 为 HIL 保留按键/触摸事件来源，增加短按/长按计数和诊断显示。
   显示诊断自动过期；震动仅接受 20–300 ms 的有界请求。
5. 最后启动核对发现电压跨过 4095 mV 后显示为 58 mV。对照官方 PM1
   readVbat 实现，改为完整小端 uint16 毫伏读取，去掉误用的 12 位掩码。
   这不等同于电量百分比、充放电曲线或续航校准。
