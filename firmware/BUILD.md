# 固件构建与烧录 / Firmware build and flashing

`esp32_p4_storage_query_control/probe` 是同源私有对照：两者使用相同的阶段留痕、
程序与后台配额、串口策略；probe 单独开启 `PET_P4_DIAGNOSTIC_STORAGE_CACHED`。
它把诊断用空间统计移到现有低优先级存档线程，每次工作完成后至多每秒刷新，
音频忙时跳过。查询只复制固定 DRAM 快照，报告可用性、陈旧度与刷新错误，不等待
SPIFFS 锁。旧的 `totalBytes/usedBytes` 保留；快照绝不能用作写入授权或持久化回执。
失败保留上一份有效统计，默认普通/UI 路径仍关闭；并未移除 fsync、改变看门狗或
声学策略。新增阶段只细分原生分配、诊断 FS 统计和 SPIFFS HAL，均在原临界区外。

`esp32_p4_watchdog_phase_probe` 为默认关闭的被动复位留痕对照，继承相同混用资源
与串口策略，不延长/关闭看门狗，不新增任务、服务权限或调度优先级。固定244字节
RTC NOLOAD 记录仅含构建摘要、每次启动随机代号和原生任务阶段数值，双槽校验及
最后提交字拒绝损坏/中断写入。只读诊断返回上一份同构建有效记录；这可能是较早的
完整记录，不证明最后指令、跨核时序或根因。周期计数器逐核回绕，不能当墙钟。
普通/UI/原混用配置不分配该记录；原始 ROM 复位原因另以两项数值补充 SDK 聚合原因。
记录钩子只在临界区外，ISR/不可让出上下文拒绝记录；不改变原有发布、撤销和音频互斥。
同镜像软件重启可验证保留，禁止为了验收故意触发故障。声学门禁仍单独保留。

`esp32_p4_query_lock_control/probe` 为私有同源诊断发送锁对照。两者记录前一条已
完成诊断查询的锁等待、持锁与解锁后发送墙钟；probe 仅把既有完整序列化响应
留到状态锁释放后，通过原路由发送一次并释放。不增加线程、队列、缓存或重试，
不延后变更 ACK、音频或媒体响应；普通、UI、原混用构建仍默认关闭。响应属于
捕获时刻，不能作为发送完成时仍未变化的证明。该实验不是看门狗根因或长帧验收。

`esp32_p4_render_pack_probe` 是默认关闭的 H264 打包对齐读写对照：先检查三处
地址的四字节对齐，再以 memcpy 保留别名语义；不对齐和尾部保留原路径。
不增加缓存、线程或优先级，不改变 PPA/LCD 围栏，普通/UI/混用配置均不启用。
主机字节一致性不等于 P4 吞吐或声学验收，须用同源原 PPA 对照实测。

本实验工作副本当前为 **0.7.103-p4-r50**。组件会话同时拒绝副本/启动重入；启动中
的停止请求锁存，在成功分配 owner 后先取消，不能被启动成功覆盖或接受新输入。
另有独立 `esp32_p4_scheduler_probe` 诊断构建，开启审计过 ABI 的被动调度/文件系统
观察及数值读取接口。普通与 UI 构建不启用 hook、环形缓冲或对应命令；该诊断固件
不是发布包或执行权限。它只覆盖跨对象 wrap 调用，不构成完整 ISR/Flash 因果证明。
可信程序宿主、运行时、计时器、事件组和
轮转调度器固定原生实例地址；误复制整个上下文不能通过执行、取消或清理接口影响
原实例的资源。实例不能搬迁或序列化，重新初始化活动存储仍是禁止的可信调用。
固定探针记录同一最慢片的起止启动时钟，便于关联诊断，不输出地址、变量或用户文本。
可信设备宿主在指令片中另用固定750us
协作式提前让出，保留续执行位置和事件顺序；时钟异常或连续八片无进展则停止，
不是硬抢占/Flash 停顿修复。固定探针新增同循环带时间策略的对照组。执行门禁仍关闭。
新程序前台生命周期锁存隐藏后的停止，
普通 tick 也不能在隐藏或仅恢复焦点时继续修改模型；明确新激活才恢复，不补跑隐藏
时间，旧非程序组件的后台计时语义不变。混合契约同时验证程序、文本草稿与页面栈。
锁内观测只采本核 cycle counter，
与整次调用的微秒 wall time 分开，host stub 不伪造硬件周期。configuredCpuHz 仅为
编译配置，不是运行时频率测量；周期差采用 uint32 模运算，观察窗口须远短于一圈。
键盘 index/label 等编辑器瞬态字段不得成为程序输出目标。队列满时新输入禁用且有
可见反馈，已接受事件仍按序完成，不丢弃或重试。实际设备 factory 绑定不可替换的原子
发布器，同一资源锁内检查 exact PROGRAM lease 并复制不超过512字节的完整状态。
音频预约/撤销与它共享线性化点；指令、驱动、等待均不在该临界区。离线并发测试
不代表临界区 P4 延时或声音/AEC 门禁已通过。UI 目标另编译受限组件程序的完整接入，
但 EXECUTION_REVIEWED 仍为0，PROGRAM 配额/设备能力保持关闭；普通目标不启用。
这不是程序执行性能、提交互斥或声学门禁通过的声明。新增父级及实际浏览器验证不能
替代这些门禁。后续需要独立受控测量，禁止为了安装测试打开执行开关。
在下述 r42 基线上，UI 候选目标另接入
PC 数据源驱动的有界可见列表：严格 JSON 声明、一次宿主捕获、标准节点绘制、
按来源/可见槽/稳定 ID 与原生观察隔离输入。普通目标默认关闭，程序/外设配额仍为零。
它不是设备独立集合程序、可编辑记录或无限动态 UI；离线/编译证据不能替代实机门禁。

r42 补强实际存储通道的固定实例所有权：复制上下文不能解锁、推进或释放原任务，活动上下文不能被其他通道覆盖；配置了任务识别却返回零时拒绝工作。正常完成后同一原生实例仍可复用，持久化未发布状态仍保留占用。ASan/UBSan 覆盖拒绝前后状态、原锁恢复及一万轮正常复用；没有改动文件命名、存档、能力配额或音频算法，尚非实机长帧/声学验收。
独立 `esp32_p4_canvas_candidate` UI 候选目标另启用有界通用 Canvas 和 UTF-8 混合表单，复用同源 C/WASM 核心；普通目标两者均关闭。新增文本表单仅保存已确认字段，中文输入法只替换草稿。冷恢复遇到不兼容/损坏存档明确拒绝发布，不以默认值覆盖原数据。这些离线能力仍须 P4 输入、字形、帧耗时和语音/AEC 门禁，不作为公开功能已完成的声明。
r27 另补只读启动 nonce、镜像 ELF 摘要与截图来源关联，以及本机构建/验收记录的统一校验入口。它不代表设备认证，也不能凭截图成功推断长帧、组件程序、外设或声学门禁已通过；详见 `tests/FRAMEWORK_EVIDENCE.md`。没有更新 PC 随包镜像或打公开安装包。
r28 把 App/媒体布局、变更图片、横版场景、确认提示合并为一次原生运行时快照；宿主文字、变量和按钮状态只捕获一份回复。锁不跨越图片解码、绘制或文件 I/O，输入仍实时核验原生身份，渲染快照不是操作授权。大缓冲复用渲染线程 PSRAM，不新增帧缓冲；未改变旧包格式或存档。另补不随统计窗口重置的启动期峰值、超预算和帧间空档计数，超过两秒的样本不会从该计数中消失。这是诊断完整性修复，不代表历史长帧或串口损坏的根因已被实机排除。
PC 实验工具另可将严格整数指令数据编码为 P4P1，并以同一 C 解码器/分片运行时作离线预览；固定内存、零 imports、无效果指令。十类纯逻辑向量在 1/7/64 指令片下与原生 ABI 比较状态/回执。它不是新增设备程序安装命令、包 schema、输出绑定或调度许可，生产执行配额仍为零。
r29 另补接收端原生输出范围的整笔事务校验：越界不发布任何状态，缩窄范围不能静默清空或截断旧存档。通用定时事件核心与离线预览共享 C，一轮至多投递一件工作，错过周期只合并、不集中补跑，队列回压保留到期事件；取消、时钟倒退和序号故障锁存停止。实际宿主租约撤销测试覆盖音频忙后的停止与旧代隔离；它不是持久闹钟、RTOS 调度接入或实际声学/性能验收。未新增自动启动设备程序、旧事件重放或组件专用分支。
r30 补原生四 owner、每人四条消息的有界整数事件总线，原子分发、单次投递、接收端代次重验和明确回压；未知/拒绝的本地入队结果不自动重试，新实例不继承旧队列。可信父策略负责授权与生命周期，关闭注册不代替运行时取消，也不释放其他能力的物理租约。它仍未开放组件协议、跨重启持久任务或真实设备调度；原生/WASM 和宿主故障回归不替代实机验收。
r31 修复已在受控原生交错中复现的摇杆诊断撕裂：独立原子字段改为固定三槽、读者 pin 保护的完整 observation，读不到完整行时 ready=false。原采样/校准判定、摇杆解码、按键映射与音频/AEC 路径不变；新缓存不调用驱动、不等待读者、不使用环绕代次来判断一致性。ASan/UBSan、ThreadSanitizer、原生输入函数交错及 P4 静态对象测试不能替代设备任务争用与时延验收，也不是对历史长帧或物理串口损坏根因的声明。

r32 为默认关闭的整数程序宿主增加不可变 UI 投影：接收端元数据推导输出范围，启动失败保留旧映射和数据，取消/音频占用/过期租约禁止再次发布。投影仅处理整数槽位，不开放组件程序安装、跨组件 UI 权限或原始外设。父级仍须将投影和实际 UI 发布置于同一生命周期锁内，并单独验证 UI 身份及资源租约；离线测试不等于设备时序验收。
导航栈核心同时抽成纯 C；PC/工具通过固定零导入 WASM 复用相同 allowed/apply，旧字符串路由和存档语义保留。非法栈拒绝操作、不自动重置数据；Python 仍是独立契约模型，不能宣称所有业务逻辑已单源。
r33 补原生稳定键集合模型和同源固定内存创作预览：最多 128 条、8 个可见槽，筛选隐藏时保留选择 ID，UTF-8 显示截取不修改原文，所有错误保留原状态。与既有 Rust PC 集合服务共跑换序/空集/失败回滚向量，并用真实 AppSurface 作合成交互验收。仍未增加设备动态列表安装协议、记录存储、混合表单提交或绘制路径；源数据验证不是渲染临界区工作，必须另过 P4 耗时、生命周期和声学门禁。
r34 将同一不可变整数 UI 投影接入可信程序准备/发布桥，当前包身份、操作代次、接收字段范围与旧存档一起验证；成功才消费准备结果，失败不覆盖原运行时或存档。发布段不读取文件，父级仍须先保存旧实例并持有实际包/UI 生命周期锁；尚未开放设备安装协议、程序配额或实际 UI 发布权限。
r35 补原生程序生命周期组，输入、定时器及订阅消息共享单调事件序号；手动停止、音频/租约撤销、时钟及序号故障收拢取消全部所属工作，旧组不能取消新代实例。历史提交和回执仍可读取，物理释放仍由真实 host 在运行时返回后执行；没有循环排空队列或自动恢复。父级共享锁、可信主题注册、实际设备调度、公平性与 P4 时延门禁仍未接通，生产程序配额保持零。
构建门禁另修正第二 DRAM 段的漏算，采用 `p4-allocated-ram-v2`，按实际地址统计内部静态分配并记录各段贡献；包含 TCM/LP SRAM 与保留、对齐区域。构建证据独立解析 ELF，旧三段求和数字及未标记算法的报告不能作为完整静态内存证明。预算不放宽，仍是 384 KiB 内部静态上限、至少 128 KiB OTA 余量；运行时堆、任务栈和音频/AEC 仍须另行验收。
r36 补齐普通运行时、协议和组件 JSON 文件的 NUL 表示检查，在 cJSON 丢失长度前拒绝；Python、JS 预览和 Rust 包校验共享语义向量。不静默截断或重写输入，不改变普通转义文字、旧身份文本和二进制图片路径；这不是完整 UTF-8/JSON 语法验证，也不代表实机串口问题已解决。
r37 增加原生四组协作轮转，一轮只访问一个组、最多尝试一个定时/订阅投递和一个程序片段；报告回压或忙实例不会夺取其他实例的下一轮。精确注册防旧代取消新组，时钟倒退和主动停止锁存所有组；忙清理保留占用，外部输入也遵守停止状态。该库没有创建 RTOS 任务、开放程序包或改变音频路径；固定配额、软件片数和原生测试不等于 P4 时延、公平性或声学验收。
构建期栈检查另覆盖 App 文字/数据、跨模块快照、混合表单和指标路径，不再仅检查媒体分支；现有 4096 字节静态路径预算与主任务 10240 字节配置不变。该手工审查路径集合不涵盖全部库/中断调用，更不替代实机栈高水位、长帧或声学门禁。
候选另补程序专用的私有 A/B 存档命名空间、精确持久化检查、可信包工作线程的准备/发布桥，以及宿主点击到命令入队全过程的原子观察校验。PC 组合源新增有界稳定 ID 集合视图；它仍投影到已有固定节点和标量绑定，不代表设备已具有动态列表或键盘。PROGRAM/PERIPHERAL 已加入实时资源排他，但生产配额仍为零；未接通可安装程序、鉴权外部写入或任意原生外设。目标编译与 host 回归不能替代实机/长帧/语音和 AEC 门禁。
候选另记录组件存储操作与画面/PPA完成回调的纯数值时间关联；这些墙钟诊断不证明秒级长帧或负载下程序时间上限已经解决。未开放任意外设、DMA 或程序包执行权限。
文件清理仅在命名空间所有权仍有效、完整目录扫描且统一 FS 活动观察无并发时合并缺失路径检查，否则保留原逐路径行为；扫描不可靠不删额外路径。该优化不取消 catalog 持久提交，不掩盖仍需处理的帧间等待，也不改变原有音频文件播放算法。
旧 SDK 正常文件 EOF 可能残留共享错误并使后续目录扫描返回 EIO。仅在首次读取失败、目录关闭成功且原所有权/活动 epoch 未变化时允许一次全新完整扫描；丢弃首轮位图，第二遍仍失败则保留原逐路径处理。它是有界兼容路径，不把 EIO 当作正常 EOF，也不重试删除。后台存档另补普通提示音播放状态检查，拒绝在已观察到音频忙时启动新的文件 I/O；此观察门禁不是跨线程音频所有权保证。
旧 Release 和 PC 随包镜像不会因源码变动自动更新；打包前仍需匹配的 v1/v3 构建与验收。

目标为 ESP32-P4、32 MiB Flash；硬件参数见 `boards/`、`sdkconfig.defaults`、`partitions.csv`。完整技术说明见 [README.md](README.md)。

## 获取与构建 / Build

只想使用设备，无需安装编译环境：下载对应芯片的 [完整烧录包](https://github.com/YizhengWw/HachimoDock/releases/latest)，按包内中文指南操作。烧录需要 Python **3.10+**，包内脚本会安装并检查 **esptool 5.4.0**；不要用旧版工具或 `--force` 绕过芯片检查。

自行构建需要 Git、Python 3.10+、PlatformIO Core **6.1.19**（6.1.18 不支持 v3 平台）。当前素材由普通 Git 保存，不依赖 LFS 额度。在独立 Python 环境中安装：`python -m pip install platformio==6.1.19 pytest Pillow`。项目通过 `platformio.ini` 固定平台版本，由其安装 ESP-IDF 和 P4 工具链；首次构建需要联网下载依赖。

| 项目 | v1 构建 | v3 构建 |
| --- | --- | --- |
| PlatformIO 环境 | `esp32_p4_evboard` | `esp32_p4_evboard_v3` |
| pioarduino 平台 | `55.03.32` | `55.03.38-1` |
| ESP-IDF | `5.5.1` | `5.5.4` |
| RISC-V 工具链 | `14.2.0_20250730` | `14.2.0_20260121` |
| 依赖锁 | `dependencies.lock` | `dependencies.v3.lock` |
| 出厂烧录工具（不同于编译环境自带版本） | esptool **5.4.0** | esptool **5.4.0** |

两种环境请依次构建，不要在同一工作目录并行构建，避免依赖环境相互覆盖。Windows 建议把仓库和构建缓存放在较短的纯英文路径（例如 `C:\work\HachimoDock`），并在 PowerShell 使用下方相同的 `python -m platformio` 命令；`tools/p4.ps1` 的默认构建目标仍是 v1。

```sh
# 仓库根目录 / repository root
python firmware/tools/build_builtin_bundle.py --check
python -m pytest firmware/tests
cd firmware
python -m platformio run -e esp32_p4_evboard
python -m platformio run -e esp32_p4_evboard_v3
```

`esp32_p4_evboard` 构建旧版芯片固件（0.1～1.99）；`esp32_p4_evboard_v3` 构建 v3.0～3.99 固件，使用 ESP-IDF 5.5.4。`esp32_p4_evboard_windows` 仅是默认环境的兼容别名。**固件按芯片版本区分，不按 Windows/macOS 区分**；两端都使用 4M UART。

微雪 ESP32-P4-WIFI6-M 的 M 表示焊接排针，不能据此判断芯片版本。**v1 与 v3 的镜像不可互刷，具体版本可以咨询客服进行确认。** 也不要通过修改最低芯片版本或强制烧录绕过检查。每次切换环境均使用对应的 `sdkconfig.<环境名>`，不要复制另一个环境的 sdkconfig。

CPU 时钟遵循 ESP-IDF 的芯片配置：v1 保持 360 MHz，v3 使用 400 MHz（v3 配置不提供 360 MHz 选项）。没有为旧芯片开启实验性超频。画面、游戏与输入继续按原有时间逻辑运行，UART 速率不变。参见 [ESP-IDF 5.5.4 时钟配置](https://github.com/espressif/esp-idf/blob/v5.5.4/components/esp_system/port/soc/esp32p4/Kconfig.cpu)。

PC 打包前，将两个环境的 `firmware.bin` 分别放入 `pc/src-tauri/firmware/esp32-p4/firmware.bin` 和 `firmware-v3.bin`。资源检查要求版本一致、芯片范围正确且来自干净提交；不要用空文件或旧镜像代替。客户端按实际芯片版本选择升级文件，未知版本不会猜测。

屏幕排线必须接 **DSI**（显示输出），不能接 CSI（摄像头输入）；请断电后插拔排线。针对配套屏幕的 v3 固件采用 24 MHz 显示时序，相关修复已在 v3 板确认恢复宠物动画。未连接摇杆或启动校准无效时，方向输入停用，连接摇杆并保持居中后重启可重新校准。

0.7.53-p4 修复了部分形象循环播放或切换状态后停止的问题。v3.2 已完成保留数据的 OTA，以及休息、工作、等待、结束和返回休息的连续播放验证；v1 已完成编译和共享播放代码的主机回归，尚未完成本版实机验证。以上不代表全部功能已验收，按键/摇杆、麦克风、完整形象下发、断线重连及断电恢复仍需分别验证。

## 完整出厂镜像 / Complete factory image

先运行 `pio run -e esp32_p4_evboard_v3 -t factory`（旧芯片改用 `esp32_p4_evboard`）。PC/设备仍使用同一套形象、组件、分区和交互配置。

`factory-config.json` 读取 `../pc/public/terrier-clips/` 与 `../pc/builtin-clawpkgs/`，把形象和组件放入出厂存储。默认构建的 factory-image 后处理脚本生成完整镜像及清单；不要将仅应用分区的 `.bin` 当作完整烧录包。

在仓库根目录执行 / From the repository root:

```sh
node pc/scripts/package-factory-release.mjs \
  --build-dir firmware/.pio/build/esp32_p4_evboard_v3 \
  --output /path/to/empty-output-directory
```

输出 ZIP 名称包含 v1/v3，内含中文烧录指南、完整镜像、分段 bin、形象/组件资料、校验清单及 macOS/Windows 烧录入口。工具读取实际芯片版本，与 Bootloader 和应用镜像都匹配后才擦除。首次烧录使用完整镜像及包内工具；日常 OTA 使用 PC 随包的应用升级镜像。

## 注意 / Caution

`esp32_p4_state_memory_parent` 是默认关闭的任务模型内存布局实验。仅将原有稳定地址
运行状态放入 external BSS，保留 ABI、互斥锁、初始化、保存和快照语义。中断、DMA、
声音缓冲、锁元数据和任务配置不变。必须用实际 ELF 核对位置、内部/外部 RAM 预算，
并重新跑固定的连续 DMA 余量和时延门槛；不把源码/模拟测试作为硬件验收。

`esp32_p4_lookup_parent` 在保存栈预算候选上仅接入受限的正向查找起点提示与精确文件
读取的数值分段。目录仍使用原临时文件和原子 rename，不直接覆盖目录代次；八描述符
池、SDK、错误、看门狗及优先级不变。查找提示是加速线索，不是文件存在或内容授权。
必须审计实际 ELF 的跨对象 wrapper 调用、默认关闭状态、DRAM/栈预算，再用安装后
双程序/串口/完整截图/保存负载验证。不能用全局统计冒充某次安装的独占物理 I/O。

`esp32_p4_save_budget_parent` 是默认关闭的保存栈预算验证候选：只把在途快照移到
受原生单所有者保护的固定 PSRAM，保留原线程 4096 字节栈、优先级 1、A/B 和
fsync。先核对真实 ELF 的快照位置/静态栈帧及普通目标关闭状态，再做静默实机保存
与栈余量验收。不得通过增加栈、关闭看门狗、重刷出厂数据或重放未知提交来掩盖故障。

私有 `esp32_p4_ota_metadata_probe` 在擦除阶段对照上仅开启可信 OTA 元数据观测，
去掉热诊断/状态查询重复 MMU 映射；不改 SDK、看门狗、时钟、优先级或回滚门限。
必须检查控制与候选 ELF 中实际的 SDK 调用差异，并完成安装后双程序实机压力
测试。普通构建不开启此项，不以一次压力测试通过宣称间歇故障根因已证明。

私有 `esp32_p4_native_erase_phase_probe` 在既有存档、双程序和传输策略上，
仅增加 SDK 擦除边界的被动阶段记录。七个 linker wrapper 各调用原实现一次，
原参数、返回值、errno、超时和看门狗配置不变。必须检查实际 ELF 调用覆盖，
并核对诊断中的 `nativeErasePhaseCoverage`；阶段相关性不是故障根因或修复证明。
普通目标保持关闭，不能把此观测固件打进公开包。

完整出厂烧录会覆盖设备上的原有配置和素材，操作前自行备份。烧录前核对板型、Flash 容量和 SHA-256，传输过程中不要拔线。Live-device tests and flashing are manual opt-in operations and are not run by source CI.

ESP-IDF 可能把本地驱动路径写入 `dependencies.lock`。提交前运行 `python tools/normalize_dependency_lock.py`，将本机路径恢复为 `$PET_P4_PROJECT_DIR/components/…`；勿提交绝对路径。
候选构建钩子另在 SCons 正常退出时恢复本项目已知组件的 path 字段，覆盖镜像未重建、bin 后处理未触发的增量编译；不修改版本、校验值、其他项目路径或普通元数据。异常退出仍以源码哈希和隐私检查为准，不忽略锁文件差异。

Packed native font builds also prepare sparse kerning maps once at boot. Rebuild
the generated header with `python tools/compress_font_kerning.py`; `--check` and
`tests/p4_font_kerning_test.py` verify it against the retained complete LVGL maps.
This changes storage placement only; glyph coverage and kerning values remain exact.

### r162 控制链路候选

`esp32_p4_program_public_candidate` 及继承的 v3 目标启用 `PET_P4_UART_CONTROL_PACING=1`：只把 drained 控制回复和截屏限制为最多 256 字节一批（含首批控制前缀），按既有 1 ms 间隔排队。串口仍为 4 Mbps；no-drain 音频/媒体路径不改变。私有 reference 开关继续独立，不等同于对声学或实机稳定性的验收。完整长度/FNV、帧耗时、栈和内存门槛保持原值，候选必须取得新的严格验收记录。

17 条审查栈路径使用 `p4-render-stack-v4`，桌面证据校验保留 v1/v2/v3 历史记录兼容；新增路径不可从新记录中省略。SPIFFS hint 与 I/O 状态的零初始化元数据使用内部 BSS，不放入 PSRAM；最终内部地址和 OTA 余量仍以实际 ELF 链接检查为准。

出厂配置与固件默认 bundle 继续保留全部 29 个内置组件。本机测试的卸载目录不参与裁剪出厂配置；OTA 尊重已持久卸载记录，不自动补回用户移除项。


2026-11-03 开发工厂布局 v2：双 OTA 各 3 MiB，storage 8.875 MiB，appearance 各 8.5 MiB。分区只随完整 USB 重新部署生效；普通 OTA 不改分区。保留每槽至少 131072 字节 OTA 余量及原有性能/栈门槛；新布局未采用私有体积优化实验。出厂 29 个组件和原始西高地视频不删减。
