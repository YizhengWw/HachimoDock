# Pet Manager 客户端设计规范

状态：生效
适用范围：`ref/` Tauri / React 客户端
实现基准：`src/styles.css`、`src/shell/Button.jsx`、`src/shell/Switch.jsx`、`src/shell/Card.jsx`、`src/shell/PageShell.jsx`

## 1. 设计方向

Pet Manager 是一个“安静的设备控制台”，同时保留桌搭子产品应有的轻松感：

- 大面积中性浅色画布承载高密度配置，避免视觉疲劳。
- 小米橙只用于当前主任务、焦点和明确的积极反馈。
- 卡片和控件像真实硬件面板：边界清楚、层级克制、状态可靠。
- 动效服务于反馈，不承担装饰；默认 140–180ms，并尊重减少动态效果设置。

一个页面只能有一个最强视觉动作。颜色不能代替文案、图标或结构层级。

## 2. 基础令牌

令牌只在 `src/styles.css :root` 定义。业务组件不得复制十六进制色值或自创间距体系。

### 2.1 字体

| 用途 | 令牌 | 值 |
|---|---|---|
| 界面字体 | `--font-sans` | MiSans → HarmonyOS Sans SC → 系统中文字体 |
| 代码/设备 ID | `--font-mono` | 系统等宽字体栈 |
| 正文 | `--font-size-base` | 14px |
| 控件文字 | `--font-size-md` | 13px |
| 辅助文字 | `--font-size-sm` | 12px |
| 页标题 | `--font-size-xl` | 20px |

正文默认常规字重；按钮和标签使用中等字重；重要状态最多使用半粗体。

### 2.2 颜色

| 角色 | 令牌 | 使用规则 |
|---|---|---|
| 画布 | `--bg` / `--bg-soft` | 页面背景 |
| 表面 | `--surface` / `--surface-muted` | 卡片、控件、悬停 |
| 主文字 | `--text` | 标题、主要数据 |
| 次文字 | `--text-soft` / `--text-muted` | 说明、元数据 |
| 品牌主色 | `--accent` | 唯一主操作、选中、焦点 |
| 品牌悬停 | `--accent-strong` | 主按钮 hover |
| 语义状态 | `--success` / `--warning` / `--danger` | 完成、风险、破坏动作 |
| 边界 | `--line` / `--line-strong` | 默认和强调边框 |

禁止用大面积品牌橙作为普通卡片背景。警告和错误必须同时给出可读文案。

### 2.3 间距与几何

- 间距使用 `--space-1` 到 `--space-10`，基础步长为 4px。
- 控件默认高度 40px；紧凑控件 34px；重要大操作 44px。
- 小控件圆角 6px；按钮 8px；卡片 12–16px；状态胶囊使用 `--radius-pill`。
- 页面内容默认不超过 1120px；宽工作区不超过 1200px。

## 3. 按钮系统

新代码统一使用 `src/shell/Button.jsx`。旧的 `btn-primary`、`btn-secondary`、`btn-ghost` 类仅作为迁移兼容层，不再作为新组件的首选写法。

### 3.1 层级

| `variant` | 视觉 | 适用场景 |
|---|---|---|
| `primary` | 实心品牌橙 | 页面或弹窗的唯一提交动作 |
| `secondary` | 白底描边 | 取消、更换、返回、次要确认 |
| `ghost` | 透明无边框 | 恢复默认、刷新、低权重工具动作 |
| `danger` | 红色文字/浅红悬停 | 删除、解除绑定等破坏动作 |
| `icon` | 34×34 透明方形 | 关闭、更多、单图标工具 |

同一操作区通常只允许一个 `primary`。取消在左、确认在右；破坏操作不能使用品牌橙。

### 3.2 尺寸

| `size` | 高度 | 场景 |
|---|---:|---|
| `small` | 34px | 卡片工具、标题栏动作 |
| `medium` | 40px | 默认 |
| `large` | 44px | 独立的重要 CTA |

文字按钮左右内边距至少 16px。只有图标的按钮必须使用 `variant="icon"` 并提供 `aria-label`。

### 3.3 内容

- 文案使用“动词 + 对象”：`安装到设备`、`保存并下发`、`恢复默认`。
- 图标放在文字左侧，常规按钮使用 14–16px 图标。
- 同一页面中，同一动作始终使用同一文案。
- 不使用含糊文案，例如“好的”“确定”“处理”。

### 3.4 状态

- hover：上移 1px，并改变背景或边框；不允许大幅缩放。
- active：回到原位，形成按下反馈。
- focus-visible：使用 `--focus-ring`，不得移除键盘焦点。
- disabled：使用 `--disabled-opacity`，同时设置原生 `disabled`。
- loading：按钮保持原宽度、显示内置 spinner、设置 `aria-busy` 并阻止重复提交。
- 持续时间明显的 USB 传输必须在进度旁提供 `danger` 层级的“中断传输”；点击后切换为“正在中断…” loading 状态，主机停止发包、板端丢弃未提交暂存，完成前不可重复点击。

### 3.5 React 示例

```jsx
import Button from "./shell/Button";

<Button variant="ghost" size="small" onClick={reset}>
  <RotateCcw size={14} />
  恢复默认
</Button>

<Button
  variant="primary"
  loading={saving}
  loadingLabel="保存中…"
  onClick={save}
>
  <Save size={15} />
  保存并下发
</Button>

<Button variant="icon" size="small" aria-label="关闭详情" onClick={close}>
  <X size={16} />
</Button>
```

## 4. 表单与选择控件

- 输入、选择器与默认按钮使用同一 40px 高度；紧凑编辑器可使用 34px。
- 标签必须与控件通过结构或 `aria-label` 关联。
- 错误紧邻对应控件，使用 `--danger`，并说明如何解决。
- 设备事件、路径和 ID 使用等宽字体；用户可读名称使用界面字体。

### 4.1 二元开关

- 所有“启用/停用”“显示/隐藏”设置统一使用 `src/shell/Switch.jsx`；不得继续用自定义 `button[role="switch"]` 或页面私有轨道样式。
- 开关统一为 38×22px 轨道、16px 圆点，关闭使用中性表面，开启使用品牌橙；页面只允许调整摆放和外部文字，不得覆盖轨道、圆点、焦点或动效。
- 必须提供可见 `label` 或 `ariaLabel`；条件内容使用 `aria-controls` 关联，禁用使用原生 `disabled`。

```jsx
import Switch from "./shell/Switch";

<Switch
  checked={enabled}
  onCheckedChange={setEnabled}
  label="显示内容"
  ariaLabel="显示自定义指令内容"
  aria-controls="custom-prompt-fields"
/>
```

## 5. 卡片、页面与弹窗

### 页面

统一使用 `PageShell`。标题区包含一个明确标题、一句简短说明和不超过两个右侧动作。

### 卡片

统一使用 `Card`。卡片用于聚合一个任务，不把每一行都做成独立卡片。

### 硬件配置工作区

按钮、旋钮等实体控件需要形成“设备位置 + 完整配置”的轻量工作区：

- 宽屏左侧放紧凑设备示意，右侧同时展示全部可配置手势；不得要求用户逐个切换控件才能检查完整映射。
- 三个同类短按按键优先平铺为三列；旋钮的短按、长按、左旋、右旋使用 2×2 网格。
- 动作选择与条件参数分层：并排手势字段保持等高；仅在选择特定动作后出现的参数（例如“自定义指令”正文）放在主工作区两栏下方，横跨设备示意与手势编辑区。参数标题对齐设备栏，输入内容对齐配置栏，并标明来源控件与手势。
- 条件参数区默认隐藏，只保留名称、数量和明确的“显示内容”开关；开关使用原生 checkbox 与 `role="switch"`，并通过 `aria-controls` 关联编辑区，开启后再渲染编辑字段。
- 宽屏的设备示意与手势编辑比例以接近 45/55 为基准；两栏应在相近的视觉高度结束，不允许条件参数只向下拉长其中一栏。
- 设备示意只解释物理位置，不重复列出右侧已有的完整映射。
- 一个任务只使用一层主要卡片；内部通过留白、细分割线和浅色字段区分分组，避免卡片套卡片、重阴影和大面积渐变。
- 事件 ID 属于实现信息，默认不直接展示给普通用户；保留在语义属性或调试信息中。
- 同步状态和唯一主操作位于工作区顶部，修改反馈不得挤占控件布局。

### 弹窗

- 使用共享 `modal-backdrop`、`modal-card`、`modal-header`、`modal-body`、`modal-footer`。
- 必须提供 `role="dialog"`、`aria-modal="true"` 和可关联的标题。
- 右上角关闭使用 `Button variant="icon"`。
- 提交期间关闭和重复提交都必须禁用。
- 页脚动作保持“次要在左、主要在右”；窄屏允许等宽双列。

组件详情/安装弹窗使用稳定的四段式信息架构：

1. 概览区：设备画面、来源标签、组件类型和一句目标说明。
2. 工作区：当前任务的可编辑配置；按钮映射保留标题、解释、概览条和逐项选择器。
3. 影响区：仅在替换、覆盖、离线或能力不匹配时出现，集中说明后果和阻断原因。
4. 确认区：左侧说明提交结果，右侧放取消与唯一主操作。

桌面端概览区与工作区并列，预览宽度稳定、配置区获取剩余空间；不要把风险提示或确认按钮混入可滚动的映射列表。概览可在内容滚动时保持可见，但窄屏必须回到正常文档流。

组件详情页的固定按钮层级为：

1. 关闭：`icon / small`
2. 恢复默认：`ghost / small`
3. 取消：`secondary / medium`
4. 安装到设备或保存并下发：`primary / medium`

## 6. 动效与可访问性

- 常规交互使用 `--motion-fast` 或 `--motion-standard`。
- `prefers-reduced-motion: reduce` 下停止位移和装饰动画；加载 spinner 只保留最低必要反馈。
- 所有交互必须能使用键盘完成。
- 正文和控件文字保持 WCAG AA 对比度目标。
- 不依靠颜色单独表达连接、冲突、安装成功或失败。
- 触控目标不得小于 34×34px，重要动作优先达到 40px。

## 7. 响应式规则

- 1020px 以下，硬件示意移到完整配置上方，保证三列短按配置仍有足够宽度。
- 640px 以下，实体控件组改为单列；480px 以下，旋钮手势也改为单列。
- 840px 以下，组件详情的主双栏转为单栏；概览内部暂时保留“预览 + 摘要”双列。
- 680px 以下，组件概览、按钮映射行和 SW 状态条全部转为单列。
- 手机端避免正文与配置列表双层滚动；列表展开后统一由弹窗正文承载纵向滚动。
- 弹窗页脚在窄屏使用两列等宽按钮；不得让主按钮掉到不可见区域。
- 按钮文案不能截断；空间不足时优先让操作区换行。

## 8. 设计变更检查清单

- 是否复用了现有令牌和共享组件？
- 页面是否只有一个主按钮？
- 默认、hover、active、focus、disabled、loading 是否齐全？
- 图标按钮是否有 `aria-label`？
- 提交期间是否阻止关闭和重复提交？
- 360px 宽度下是否仍能完整操作？
- 是否更新了本规范、对应 `.folder.md` 和测试？
