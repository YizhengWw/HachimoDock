## Architecture
- 2026-08-06 cross-Mac Codex voice recovery: exact Session ID deep links keep
  title verification as the first path. If a Codex/macOS combination hides the
  active title from Accessibility, voice delivery reselects only a unique
  matching sidebar row before pinning its composer; ambiguous or missing rows
  still fail closed instead of typing into an unverified foreground task.
- 2026-08-06 client-authoritative input reconciliation: board config reads and
  writes wait behind firmware/asset transactions, preventing reconnect-window
  query timeouts. The desktop compares the complete persisted PC mapping with
  the returned device mapping and automatically overwrites any difference;
  board state never replaces the PC cache.
- 2026-08-06 desktop `0.1.23` session/input correction: the P4 queue dedupes
  event and snapshot records using exactly the visible title/body-or-state
  tuple. Global button actions are fully repeatable, voice may use multiple
  long-press gestures, and users may leave every action—including exit—unbound.
  Component Center waits for the connected board's authoritative optional exit
  binding before validating a package and never invents an SW1 fallback.
- 2026-08-06 schema-5 firmware recovery feedback: firmware progress accepts a
  `recover` stage while the backend rebuilds a transaction cleared by affected
  old firmware; the normal schema-6 path remains unchanged.
- 2026-08-06 bundled-firmware release marker: desktop `0.1.16` compares P4
  devices against embedded `0.7.33-p4`; no component-package revision or
  resynchronization is required for the firmware-only input-isolation fix.
- 2026-08-05 bundled-firmware release marker: desktop `0.1.15` compares
  connected devices against the embedded `0.7.32-p4` image; the existing
  sidebar update action remains the single user-facing OTA entry point while
  native transport handles adaptive recovery.
- 2026-08-05 global-exit component UI: Component Center queries the connected
  P4's authoritative `page_back` binding, removes legacy system-navigation
  rows from component previews, disables whichever physical option is the
  current global exit, and blocks sync until an old conflicting gameplay action
  is remapped. Built-in fixture copy and controls now match SW1 global exit plus
  SW3 primary/start behavior.
- 2026-08-05 board-default hydration repair: `DeviceDashboard` recognizes only
  the complete former shipped P4 mapping before changing SW1 Confirm/SW3 Back
  to SW1 Back/SW3 Confirm, then ACK-gates an automatic writeback. Any custom
  gesture prevents the automatic migration and remains board-authoritative.
- 2026-08-05 sidebar firmware module: `App` mounts a label-only module below
  API Configuration with no routed detail page. It compares the verified USB
  firmware against native bundled-image metadata, renders Update only for an
  older P4, renders non-button Up to date for equal/newer versions, and streams
  the existing OTA progress/toast feedback through an in-place update.
- 2026-08-05 P4 navigation-default v7: `DeviceDashboard` and the device guide
  now define SW1 short as Back (Cancel) and SW3 short as Confirm/Enter. The
  model-v7 cache migration replaces only unchanged model-v6 defaults; custom
  button choices, SW1-long PTT, SW2 Component Center, and joystick mappings
  remain intact.
- 2026-08-04 transient Session/card and input-model correction (superseded by
  the fully repeatable `0.1.23` policy): the device
  queue collapses visually identical event/snapshot identities before USB
  downlink, preventing a second matching card from flashing during work or
  completion. Client input-cache model v6 migrates the former SW1-short
  unbound default to Confirm while keeping joystick-center long press unbound;
  Confirm was the first repeatable non-disabled navigation action so SW1 and
  joystick-center short press could both enter without clearing one another;
  Tauri now accepts `joystick.up`/`joystick.down` during ACK-gated sync.
- 2026-08-04 all-Agent joystick Skill distribution: the single bundled
  `petui` source now documents four-way joystick choices, the SW1/SW2 game and
  tool conventions, and explicit SW3 component exit. Pet Manager installs the
  same validated Skill tree into every detected Codex, Claude, OpenClaw,
  MiMoCode/Agent Skills, Gemini CLI, and Cursor home so Agent behavior does not
  diverge.
- 2026-08-04 default-component control standard: all seven bundled components
  reserve SW3 short press for `page_main`. Games use SW1 for start/restart
  (Flappy retains its combined flap/start action); gameplay directions move to
  the four-way joystick, including Blocks left/right/up-rotate/down-drop.

  packages may opt into `joystick.up` and `joystick.down` explicitly.
- 2026-08-04 desktop release-version regression coverage: packaging tests keep
  the npm, npm-lock, Cargo, and Tauri desktop versions synchronized and require
  the stable local macOS bundler to derive its DMG filename from the configured
  product, version, and native architecture rather than a fixed `0.1.0` name.

- 2026-08-04 native macOS Accessibility destination flow: the app shell and

  compatibility ID that could end on the Privacy & Security root. Dashboard-
  created permission Toasts are not used, and explicit recheck stays
