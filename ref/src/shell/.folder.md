# Folder Plan: ref/src/shell

## Architecture
- 2026-07-30 focused appearance refresh and UART status update:
  `DeviceContextProvider` exposes a force-refresh limited to appearance
  records for immediate picker use, while normalized USB state retains the
  protocol-verified `baudRate` for cross-platform transfer diagnostics.
- 2026-07-30 P4 USB-only reachability cleanup: `DeviceContextProvider` derives
  device availability solely from a verified USB snapshot and no longer polls
  Bridge Wi-Fi availability. Legacy binding identity and configured SSH
  component targets remain temporarily readable for the next cleanup phase.
- 2026-07-29 first-run Agent default: `DeviceContextProvider` initializes and
  falls back to the shared Codex default only when local storage has no
  selection; Bridge hydration continues to override it with an existing
  explicit choice.
- 2026-07-29 USB-only follow update: `DeviceContextProvider` stopped
  reconciling a board's followed source or desktop id from MQTT availability.
  Explicit user follow changes are handled only by the verified USB assignment
  workflow; the remaining read-only Wi-Fi poll was removed on 2026-07-30.
- 2026-07-28 per-page onboarding update: `PageOnboardingModal` provides a
  compact three-step first-visit dialog. Each page persists its own “do not
  show again” preference, can clear that preference by unchecking the switch,
  and keeps the PageShell help action available for later reopening.
- 2026-07-28 Agent rescan update: `DeviceContextProvider` owns `agentScan` metadata and a request-deduplicated `refreshAgents()`. It scans once at startup, on explicit requests, and when the visible app regains focus after a 30-second stale interval; there is no fixed Agent polling loop.
- 2026-07-27 cancellable appearance-transfer update: `DeviceContextProvider` keeps the cancellation-request state alongside persistent USB appearance progress and exposes `cancelAppearanceSync()`, so the dashboard action survives tab mounts and cannot be double-submitted.
- 2026-07-27 shared switch update: `Switch.jsx` provides the single native checkbox-backed `role="switch"` track/thumb/label contract now reused by voice enablement, custom-prompt disclosure, and Codex conversation visibility.
- 2026-07-27 shared button update: `Button.jsx` is the semantic entry point for primary, secondary, ghost, danger, and icon actions, with small/medium/large sizing plus built-in loading and disabled semantics. The component-center detail surfaces are the first migrated consumer; `ref/design.md` is the normative usage guide.
- 2026-07-27 component-target update: `DeviceContextProvider` resolves `currentComponentTarget` from a verified live USB board first, then the configured SSH host, then a remembered board id, and reads only that target's v2 active-component record. Same-tab and cross-tab storage events refresh the record without inferring a device for legacy global state.
- Scope: ref/src/shell
- Function: Cross-page shell primitives that compose every page in the manager — PageShell (header + actions + help), Card (with Collapsible variant), ToastStack (provider + hook + presentational stack), DeviceContextProvider (single source of verified USB reachability, binding/appearances/agents; normalizes runtime only from verified protocol metadata; hydrates the active channel from the bridge profile before trusting localStorage so stale UI cache cannot mark an unsynced appearance as current; exposes a manual `refresh()` that force-reloads disk-backed appearance records before picker flows; owns the in-flight appearance USB sync progress and cancellation state so dashboard tab unmounts do not reset the visible downlink task; leaves follow-source changes to explicit verified-USB user actions; Rust owns background serial auto-connect; exposes manual USB serial rescan/connect that walks every candidate until a protocol hello verifies the device), ContextRail (sidebar bottom rail showing the device/appearance/component triad).
- Sync: if this folder changes, update this file immediately.
- Reuse: consumed by `App.jsx` (provider wiring + sidebar mount), and by every page in `ref/src/*.jsx` after Plans 2/3/4 migrate them. Pure derivations like `deriveCurrentDisplay` are unit-tested via `node:test`.
