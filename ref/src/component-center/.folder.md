# Folder Plan: ref/src/component-center

## Architecture
- 2026-08-04 joystick component-input update: component editing and package
  validation accept explicit `joystick.up`/`joystick.down` actions. Left/right
  and center keep their legacy rotary event identifiers, so prior `.clawpkg`
  files remain installable and run unchanged. Button-config model v5 includes
  the complete joystick-aware compatibility snapshot without overwriting the
  device's global navigation bindings.
- 2026-08-03 unified library update: Component Center removes the separate
  device browser and deferred batch plan. Live board inventory is still the
  source of truth, but each library card now owns one immediate two-state
  action: sync when absent, remove when present. Formal-local trash is a
  device-first transaction when installed, so a failed board ACK preserves the
  PC source. Unknown board-only packages are folded into the same grid as
  read-only, removable records. Redundant library title/search/count chrome and
  top-right preview status overlays are removed; type filters and bottom device
  actions remain.
- 2026-07-30 Windows preview-performance update: shared component game
  previews run their blocks/snake/flappy timers only while the document is
  visible and the individual device screen is inside a bounded viewport margin,
  preventing offscreen library cards from continuously rebuilding pixel grids.
  Visible dynamic grids draw into one pixelated Canvas instead of mutating up to
  160 individual DOM cells per frame.
- 2026-07-28 button-model v4 update: the shared device-button cache advances
  with the revised global navigation defaults (SW2 Component Center, SW3 Back,
  encoder-long unbound) so version-3 defaults migrate without replacing
  unrelated user mappings or component-owned controls.
- 2026-07-28 button-model v3 update: the shared device button cache version advances so the dashboard can migrate version-2 defaults to the simplified P4 map. Component-owned `miniapp_action` compatibility helpers remain package-internal and are no longer exposed by the global button dropdown.
- 2026-07-28 library ordering update: `library-order.js` normalizes ISO/numeric
  timestamps for stable newest-first sorting of generated packages. Builtins
  now retain their explicit product order ahead of that generated list.
- 2026-07-28 native-game field refinement: animated blocks/snake/flappy
  previews remove the thick pale playfield card and heavy grid shadow in favor
  of a palette-tinted field, 1px dark borders, and two pixels of inset. The
  Flappy preview path also mirrors the board's gentler one-tap climb.
- 2026-07-28 widget visual-parity update: the client preview and P4 renderer
  resolve pixel-tool accents from the same safe palette meanings
  (`candy=amber`, `sunset=coral`, `mint=aqua`, `arcade=violet`) and resolve
  semantic icons from `visualSprite`, so a synchronized package no longer
  changes its visual identity merely because it moved from React to firmware.
- 2026-07-27 modal-safety update: the preview modal traps Tab, closes on Escape, restores the opener, explains single-slot replacement without claiming the old package remains, and turns unknown device-only packages into read-only details with no install action.
- 2026-07-27 component button-scope update: component install/update writes the customized bindings into the package only. The modal explains that those mappings activate only while the component is open and do not overwrite Pet Manager's persisted encoder enter/back navigation.
- 2026-07-27 enabled-component lifecycle update: the library keeps the currently enabled item visible, resolves every card from explicit `kind` metadata before the legacy `gameType` fallback, and exposes semantic `aria-current` state only for an exact, target-verified source. Device removal and formal-local dual deletion both freeze the exact target in a focus-safe confirmation dialog.
- 2026-07-27 detail-button unification: the current-component hero and component preview/editor now render every conventional action through the shared shell `Button` primitive. Close, reset, cancel, install, and save each use the hierarchy documented in `ref/design.md`; install state also owns accessible loading and prevents backdrop dismissal.
- 2026-07-27 detail-layout refinement: the component preview/editor now uses a stable overview/workspace split, keeps the device preview and component summary together, isolates button mapping in its own configuration surface, consolidates conditional risk into a semantic impact bar, and adds a contextual confirmation footer. It collapses progressively at 840px and 680px without hiding the primary action.
- 2026-07-27 seven-gesture update: component button choices now expose SW1/SW2/SW3 short press only plus encoder short/long/left/right. Built-in `page_main` exits moved from SW3 long press to encoder long press, while full downlinks explicitly disable legacy SW long/hold events.
- 2026-07-23 encoder-long snapshot update: the complete component button map now mirrors the encoder long-press event into the dashboard's `p4_encoder_long` row after an ACKed install.
- Scope: ref/src/component-center
- Function: Sub-components for the Component Center page: reusable component previews/cards and the final sync/editor modal. The preview gives bounded blocks/snake/flappy grids a game-first field with a compact score HUD and retains semantic pixel sprites. Cards expose live sync/remove state directly; the modal edits package-owned inputs, reserves device-level navigation, exposes device removal and PC/dual deletion, and blocks unsupported firmware or conflicting bindings.
- Sync: if this folder changes, update this file immediately.
- Reuse: Card imported from `../shell/Card.jsx`; CSS tokens from `../styles.css`; button options and retained compatibility map helpers stay centralized in `button-config.js`.
