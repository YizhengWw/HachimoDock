## Architecture
- 2026-08-05 desktop `0.1.11`: board hydration recognizes the complete shipped
  model-v6 P4 map, migrates only that exact default to SW1 Back/SW3 Confirm,
  and writes the corrected map back to the connected board. Firmware OTA uses
  Base64-friendly sub-4-KiB JSON chunks to avoid USB serial corruption.
- 2026-08-05 desktop `0.1.10`: npm, Cargo, and Tauri versions advance together
  for the SW1-back/SW3-confirm defaults and bundled P4 firmware updater. The
  release preflight now rejects dirty or untraceable embedded firmware before
  any desktop package is produced.
- 2026-08-05 sidebar bundled-firmware update: the shell adds a no-detail-page
  firmware module directly below API Configuration. A verified P4 older than
  the packaged `0.7.29-p4` image gets an inline Update button; equal/newer
  firmware gets non-interactive Up to date copy. Native code rechecks board
  identity, runtime, and numeric version before starting the existing
  ACK/SHA-verified A/B OTA transaction.
- 2026-08-05 P4 navigation-default v7: the desktop's fresh and reset mappings
  now use SW1 short for Back (Cancel) and SW3 short for Confirm/Enter. Cache
  migration rewrites only model-v6 values that still match the prior defaults,
  preserving custom mappings while keeping joystick-center Confirm repeatable.
- 2026-08-04 P4 button-sync and Session-card correction: Tauri's button-map
  validator accepts both joystick axis events already supported by the client
  and firmware, so a 12-gesture map no longer fails before USB downlink. The
  React Session queue also collapses transient event/snapshot aliases before
  sending `session/current`, and input-cache v6 makes SW1 short Confirm.
- 2026-08-04 bundled-component input normalization: all seven PC-bundled P4
  packages now use SW3 as the consistent exit gesture. Games use SW1 for
  start/restart and place directional actions on the joystick; tools retain
  their primary SW1 and secondary SW2 actions and move displaced third actions
  to joystick directions. Every changed manifest advances its patch version,
  so same-ID installs replace older device packages deterministically.
- 2026-08-04 P4 joystick/protocol update: desktop build identity advances to
  protocol schema 5. Input-config model v5 and package validation expose the
  new `joystick.up`/`joystick.down` events, while joystick left/right/center
  keep the legacy rotary event names so old packages and saved bindings remain
  valid across both the new joystick board and encoder-era boards.
- 2026-08-04 macOS image-task voice submission: the native foreground
  composer now accepts a semantic Send control only when its Accessibility
  bounds are aligned with the pinned bottom composer (with a bounded shared-
  ancestor fallback when geometry is unavailable). Image-result card actions
  elsewhere in the window can no longer consume the final voice submission;
  the confirmation window is three seconds so a valid Codex renderer clear is
  not rejected during a short UI settle.
- 2026-08-04 desktop version bump: Pet Manager is now `0.1.5` across Tauri,
  Cargo, npm, and npm lock metadata. Local macOS output names are derived from
  that shared release version, making current packages distinguishable from
  older `0.1.0` builds without changing the stable Accessibility identity.
- 2026-08-03 Codex pet v1/v2 atlas compatibility: the native importer accepts
  both legacy 8×9 sheets and `spriteVersionNumber: 2` 8×11 sheets, infers the
  version for legacy manifests without the field, and rejects version/height
  mismatches. The shared first nine animation rows keep the existing family
  mapping; v2's final two 16-direction look rows are intentionally not converted.
- 2026-08-03 promoted two-key catch builtin: the validated `two-key-pong`
  1.1.1 package is bundled as a desktop install resource and pinned to the first
  Component Center card. Only its exact promoted formal-library hash is hidden
  as a duplicate; other generated packages keep their newest-first order. The
  superseded `falling-catch` package has been removed from desktop resources.
- 2026-08-03 component creation-flow simplification: Component Center lists
  newest generated packages before builtins and reduces its third creation
  step to a single formal-library refresh. Manual `.clawpkg`/zip drop, picker,
  frontend state/handlers, and the unused `import_component_to_library` Tauri
  command are removed; package inspection for device sync and Skill-owned
  atomic publication remain available.
- 2026-08-03 macOS foreground composer activation and recovery: current-visible
  device voice launches or restores the followed ChatGPT/Codex or Claude app,
  requests AppKit activation, waits until the Agent is verifiably frontmost,
  and accepts a composer only after its AX node remains stable across a focused
  rescan. If Chromium later recreates that node inside the same pinned primary
  window, live/final delivery safely rebinds to the new unique composer instead
  of reporting a false session change. A verified composer may replace an
  existing draft by explicit product policy; multiple composers, a changed
  top-level window, or another application still fail closed.
- 2026-08-04 macOS 26 Accessibility destination correction: startup
  and protected foreground operations request Apple's native consent alert
  only while the current stable build is untrusted. No settings URL opens in
  parallel with the alert: one guarded watcher waits for the user's Apple-owned
  “Open System Settings” action to activate System Settings, lets native routing
  settle, then opens the exact `Privacy_Accessibility` pane once through macOS
  26's current `com.apple.settings.PrivacySecurity.extension` identifier. The
  former `com.apple.preference.security` compatibility route could briefly show
  Accessibility and then collapse to the Privacy & Security root on macOS 26.3.
  Even the current route must wait four seconds for a cold Privacy extension to
  finish rebuilding its navigation stack; routing at 1.2 seconds produced the
  same flash-and-collapse race. The delayed current route remains on the toggle
  list. The local macOS DMG workflow still verifies one stable
  `com.petmanager.desktop` designated requirement so rebuilt packages retain
  the same TCC identity.
- 2026-08-03 foreground voice and stale-session recovery: Windows ChatGPT
  discovery preserves a valid top-level window handle when Store-packaged
  Chromium reports an infinite UI Automation rectangle, explicitly restores
  and rebinds a finite accessibility root before reading the task/composer,
  skips stale utility windows, and uses double geometry overloads so `-Infinity`
  can never be coerced to `Int32`. Volcengine streaming keeps one
  20ms PCM chunk pending and marks that real final chunk as the ASR end packet
  instead of sending an empty final payload. Codex rollout bootstrap restores
  active state only when the mapped state event's original JSONL timestamp is
  still within the configured stale window; a freshly touched old rollout can
  no longer revive a historical device card.
- 2026-08-02 cross-platform empty-queue Agent activation: device voice with
  no visible Session card now follows the same contract on Windows and macOS
  for current ChatGPT/Codex and Claude Desktop clients. An already-frontmost
  app keeps its current empty composer; a background or minimized app is
  restored and raised; an app without a window is launched through its
  installed Windows AppsFolder ID or macOS bundle ID/name before composer
  focus. macOS discovery includes the current `com.openai.codex`,
  `com.openai.chat`, and Claude bundle IDs. Claude activation never uses a
  Session deep link, so it cannot create a General Coding Session.
- 2026-08-02 Windows Codex voice containment update: the foreground-composer
  helper now starts Codex's packaged app when no top-level window exists,
  prefers an Edit-only UI Automation query, and limits its semantic fallback
  to 3500 nodes, 48 levels, and 1.8 seconds. Each PowerShell helper is assigned
  to an independent kill-on-close Job Object with a 512MiB process-memory
  limit, and its seven-second startup deadline finishes before the desktop
  voice pipeline's eight-second preparation wait. A 120ms Chromium settle
  window prevents the immediate post-keyboard TextPattern read from blocking
  after the transcript has already appeared. This prevents failed voice
  attempts from leaving multi-gigabyte orphan scanners while preserving the
  existing macOS path.
