# Desktop source (0.1.197)

- USB transfer JSONL uses a central bounded diagnostic schema: numeric/boolean
  metadata and fixed labels only. Paths, content hashes, stable identifiers,
  arbitrary errors and unrecognized nested peer fields are excluded.

- PC-online program autostart binds explicit consent to exact board/content,
  native checksums, boot and connection generation. One bounded native worker
  handles connection/preemption events outside RX; the formal-library and USB
  guards span revalidation and one fixed start payload. Journal unavailability
  disables only this optional service. USB status exports exact string u64
  connectionId and validated bootId; ended music still blocks component sync.

- Serial probes propose a fresh bounded connection nonce on the existing bind;
  an offer-capable board must echo that exact nonce in a guarded HELLO before
  admission. Confirmed sessions keep it in later ACKs and reject stale/downgrade
  HELLOs before any waiter. Boards predating negotiation retain their legacy
  framed/plain behavior. Malformed proposals never become a silent legacy reset.
  This is downstream corruption detection, not authentication or task replay.

- Explicit framework uploader acceptance is separate from the read-only
  graphics transport acceptance. It uses the actual production installer for
  one exact independently authored silent fixture, pins board/boot/ELF and all
  package bytes, and only removes that fixture with preserveSave after a known
  successful commit. Unknown results are retained without mutation replay.
  It does not run automatically, read user stores, or authorize new services.

- Unparsed-line diagnostics now retain rare exact-prefix firmware fault hints
  independently of generic text rate limits. Only fixed categories/counts are
  logged, never the original text, task names, pointers or private payloads.
  Hints are not authenticated reset evidence. Explicit diagnostic acceptance
  failures may make one NEW bounded read-only identity observation to separate
  a reboot from a lost reply, without clearing failure or replaying any query.

- Experimental downstream serial control integrity verifies original raw body
  length/FNV before UTF-8 and JSON, then latches the verified HELLO policy for
  that exact connection before resolving any waiter. Legacy boards stay legacy;
  a later HELLO cannot downgrade a required policy. Audio/media and four exact
  existing screenshot reply topics retain their independent paths. This is
  accidental-corruption detection, not authentication, upstream protection or
  permission to replay an unknown mutation. Numeric-only logarithmic rejection
  diagnostics never retain payloads, hashes, IDs or paths. The actual reader,
  byte/timeout fragments, legacy tail and shared C/Rust UTF-8 vectors are covered
  by an exact offline test allowlist; no ignored tests, GUI or device startup.

- Private installed-program control uses typed, sanitized native status and
  exact string uint64 registrations. Real USB methods read complete inventory
  and verified installed checksums before a single explicit start; stop keeps
  the observed boot/registration. Unknown results are never replayed. The
  React provider only appears with explicit capabilities; hidden UI stops
  observation, not the device task. All three commands use the existing
  local-only Tauri permission, never a community/remote bridge grant.
- Offline source evidence now includes all Tauri permissions/capabilities,
  build.rs and platform configurations, not just native and frontend source.
  Browser/mock and synthetic writer checks do not certify real GUI/device
  operation, resource mixing, sound or AEC.

- Screenshot writer failures may additionally carry one fixed bounded numeric
  observation, mapped to allowlisted budget/driver/drain/lease/audio categories.
  Unknown fields/text/types and impossible counters are dropped. Tick counts

  partial writes and all other device errors still fail closed.
