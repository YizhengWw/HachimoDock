# 客户端目录

Agent 探测在阻塞工作线程运行，不阻塞界面；手动刷新仍重新解析 PATH 与 npm 安装目录。
USB 状态读取在传输占锁时返回快照，连接、握手、断开及写入失败同步更新快照；
发送与固件芯片校验仍读取真实连接。Windows 与 macOS 独立配置 H.264 编码参数，
输出仍须通过 P4 码流结构与解码校验。
Codex 回复兼容两种日志事件并按轮次配对去重，只展示公开回复通道；
工具执行时保留当前轮最近的公开回复，无回复才显示工具状态；新轮次清空旧回复。
恢复会话文件保留原始线程 ID，不把 writer UUID 当作新会话。
Desktop 诊断数据库只读兜底：单批最多 512 条、状态缓存最多 256 项；
只接受已知非内部会话，不让旧日志覆盖新轮次，不对外输出日志正文。
Bridge、语音生命周期、会话绑定与音频信令在工作线程执行，界面端按队列保持会话及音频启动/停止顺序。
Windows Claude 最小化时恢复原有窗口并重新获取输入树，失败时不创建新会话。

0.1.55：Windows 保留超时前的串口半帧，首次高速探测等待设备启动，
切速复用端口并释放 DTR/RTS。最近成功速率缓存于当前进程，连接诊断写入
现有 USB 日志。两端按芯片选择 `firmware/esp32-p4/firmware.bin`（v1）或 `firmware-v3.bin`（v3），保留旧 2M 固件的连接兼容。
正式客户端仅从安装资源查找内置固件，源码目录回退只用于开发模式。
`usb_serial/firmware_chip.rs` 集中验证芯片范围：新固件上报实际修订号，旧固件只在诊断信息证明是 v3 支持之前的 SDK 时走 v1 路径。未知芯片不自动升级，检查发生在擦除或中止其他传输之前。

- `src/`：React 界面和测试。
- `src-tauri/`：Rust 后端、设备通信及 Node Agent 连接服务。
- `scripts/`：构建、资源准备及检查脚本。
- `skills/petui/`：组件生成 Skill。
- `builtin-clawpkgs/`、`public/terrier-clips/`：与固件共享的内置组件及形象。

开发和测试命令见 [README.md](README.md)。
