# 有来源的每日一期资讯（PC 宿主能力）

## 0.1.156 每日期次与预热

客户端启动后检查本机已启用资讯组件，并独立检查北京时间跨天；不依赖USB连接。
当天成功一期后不重复生成。进入只读缓存，不触发模型。每日最多3次尝试，失败分别退避15、30分钟；
调用前落盘次数，重启不重置；缺配置不消耗次数。
完整9条原子落盘后才替换上一期。刷新失败不清空旧内容；最近一期可保留48小时供播放，
画面和开头播报均明确日期，不把昨日内容标作今日。24小时来源窗口按生成时刻核验，不逐秒作废整期。
正在朗读时的新一期下次进入生效，不抢占播放。USB断开只停止播放，不取消公开资讯整理；停用组件取消整理。
资讯专用语音磁盘缓存按正文、音色、语速、模型和协议版本寻址，PCM附摘要校验，原子保存；
总量128MiB、最长7天，仅加载有界分段。其他知识库、语音对话不自动启用该缓存。
后台合成不出声、不录音、不使用USB媒体会话；实时对话、按键语音和其他播放优先，后台让路。
上次宠物音色只用于断线预热；实际播放仍要求当前宠物音色心跳。首次无缓存或网络不可用不承诺立即播最新。
只读取豆包配置生成资讯，不要求另一个对话模型再整理。模型输出与工具引用的对应检查不触发网页抓取。

使用 `pc/application.json` 的 `engine: pc-app-news-v1`、`service: news`，
`schemaVersion: 1`。资源包不携带模型 Key、用户聊天、脚本或桌面 Agent 操作。
不新增设备专用引擎：布局使用 `p4-app-surface-v1`、graphics/type、`p4-input-v1`。

`content` 精确三项 `{id,title,query}`：id 为唯一 `[a-z-]{1,24}`，title 最多
30 UTF-8 字节，query 最多 120 字节；均非空、无控制字符或 URL。它们是公开搜索主题。
固定每类三条、滚动 24 小时、摘要 50–150 Unicode 字符，总计九条。
动作必须完整映射 `refresh/toggle/previous/next/up/down`，不支持任意宿主命令。
SW1 更新，SW2 播报/停止；左右换条、上下翻正文。触屏使用相同动作，底栏键帽
引用真实映射，退出遵守全局设置。PC 只打开预览/轮询不会生成或播放。

设备连接后复用同一后台准备任务，不播放、不切换页面；进入组件只读取完整最近一期。
资讯检索和播报文案一并使用豆包 Responses API 自带的 web_search / search_engine。
切换对话模型不会切换资讯搜索商：仅读取已保存的豆包模型 Key，绝不借用其他模型或 TTS 凭据。
当前选择豆包时沿用用户模型 ID，否则使用豆包预设模型；不改写用户的默认配置。
联网开关关闭或豆包凭据缺失时明确提示，不用模型记忆编新闻。
三类各一次联网请求，豆包自行组合具体关键词并直接返回每类三至五条完整正文，PC采用合格的前三条。
科技范围含AI、大模型、智能硬件、机器人、芯片、消费电子、航天等；财经含宏观、消费、
财报、产业政策、贸易、电商等；娱乐含影视、综艺、音乐、演出与文化产业等。
PC不抓取引用网页、不依赖网站HTML和可访问性、不再调用另一个模型二次改写。
每条正文须关联本次原生搜索实际返回的公开来源，发布时间使用工具返回时间，或豆包基于
搜索提供的带时区发布时间；不能把这种归因称为PC独立核验。缺失、未来或超出24小时拒绝发布，
不从URL推测日期，不把日期补成午夜。来源URL只作引用记录，不自动请求。
资讯搜索等待上限为90秒，整个任务仍为240秒；普通实时对话搜索仍为30秒。
三类主题最多三路并行，每路最多3组关键词、3次原生工具调用、每次工具12个结果、4000输出token。
引用收集最多48条，避免第二、三次搜索的来源被首轮12条截断；普通实时问答的预算不改变。
使用Responses的text.format严格JSON结构，不另付费调用模型修复格式。
合并时再次跨类别去重，任何类别不足三条仍不发布。设备显示实际处理阶段与耗时，
失败区分本地资源未安装、配置缺失、检索失败、来源不足和文案校验，不能笼统提示校验失败。
豆包编辑直接选出每类3个不同事件，不把整个小时热榜当一条新闻；
转载标题和最终文案均做重复事件检查，不以不同URL冒充不同新闻。
不使用豆包 Custom 搜索源，也不要求额外开通该服务。
来源不足、过期、分类不齐、长度异常或重复引用均不发布；模型整理失败不自动重试付费调用。

`autoRead:true` 只在真实设备可见时生效，使用当前宠物音色、全局音量，
从选中条目连续读至最后一条；停止不会因轮询恢复，换条会中止旧音频。
采用通用有界连续朗读队列：最多32项、总计16000字，后台预取后续语音，
同一批次复用一个设备音频会话，不在每句话之间重新连接或等上一句结束才合成。
标题、条目编号和正文页面跟随实际播放进度（已发送采样减去设备缓冲），
不能用“已开始合成下一条”作为切换画面的依据。正文翻页按分段音频时长估算，
不是逐字时间戳；用户手动翻页后，本条保留手动页，下一条再恢复自动跟随。
正文分页读取资源包 note/footer 文本节点的宽度、字号、行高和高度，并使用
设备内置字宽、字距与包内字形子集度量；不能固定按 45 字切成上下两块。
相邻文本块按连续行高摆放，每槽仍不超过 156 UTF-8 字节，全文拼接无损。
自动朗读翻页与手动翻页使用同一分页边界；排版调整不增加设备固件能力。
翻正文不重启朗读。退出、切换停止朗读并取消前台生成；连接触发的静默预取可以继续。
断线取消全部在途任务；旧任务不得覆盖新会话结果。
调用模型仅发送公开主题与编辑要求，检索内容视为不可信资料，不传个人资料，只开放原生只读搜索。
PC 详情显示原文链接与发布时间；内容仅供了解新闻，不代替投资、医疗等专业判断。

验收必须分开报告：结构校验、离线网络模拟/时间与长度校验、PC UI、真实联网
完整九条、USB 朗读。结构通过不等于真实联网或设备已通过，不伪造验收结论。
