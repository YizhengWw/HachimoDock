# 统一输入策略（p4-input-v1）

目标设备必须报告 `widgetInput: "p4-input-v1"`。PC 同步前检查能力，旧固件拒绝安装，不静默忽略策略。此能力随 0.7.92 固件开发，结构/离线通过不代表某块设备已安装或验收。

```json
{
  "input": {
    "engine": "p4-input-v1",
    "repeat": ["move.left", "move.right"],
    "swipe": {"left": "page.next", "right": "page.previous"},
    "confirm": {"timer.reset": "重置本轮计时？已完成记录会保留。"}
  }
}
```

- `repeat`：最多 8 个已声明且绑定方向输入的动作。只允许对连续位移、音量等安全动作开启。确认、删除、跳过、切台、硬降、翻模式不得连发。首个方向动作仍正常执行，默认不连发。
- `press`：最多 8 个动作，当前仅允许木鱼 `instrument.strike` 或旧飞鸟的 flap 动作，并必须绑定 SW1 短按。按下立即响应，释放不再执行一次；若该物理键被全局退出、实时对话或 hold 绑定占用，仍保留全局优先级，不能偷走长按。
- `swipe`：可选 left/right/up/down。必须是已声明 transition。有效手势小于 700ms、主轴至少 40px、主轴至少为次轴的 1.5 倍。未声明的滑动不执行动作，也不把组件内滑动解释为全局退出。
- `confirm`：最多 3 个 `action: prompt`，提示为 1–120 UTF-8 字节。第一次操作只弹确认，不执行；触屏确认/取消，或组件 SW1/SW2 对应动作确认/取消。全局退出/实时对话优先。30 秒超时或上下文更换使请求失效，不自动重试。
- `cooldown`：最多 3 个 `action: 毫秒`，范围 250–60000。仅本地运行时使用，
  不与 host/media/instrument 混用。一次有效操作后触屏与实体输入共用冷却；
  冷却中禁用控件，不排队补执行；不写闪存。养成互动可用它避免快速连按刷成长。
- `drag: {entity, axis}`：可选受控场景拖动，axis 为 x/y/xy。只支持已有 `scene_view`
  的开放网格场景，entity 必须存在且 bounds 为 clamp。游戏活动状态下，在非按钮的场地区域
  按下并移动会调整该实体中心；释放、取消、暂停、退出或换包结束拖动。
  不补演 tick、不因重复 move 事件额外计分，屏幕外坐标夹到场地边界。
  这是网格拖动，不是连续物理坐标或任意节点拖拽；原有摇杆动作仍须可用。
- 动作能否执行由当前状态下是否存在匹配 transition 决定。无匹配动作不接受点击，并表现为禁用。
- 对实时列表的纯翻页动作，只有会改变实际显示页时才可执行：空列表和单页时不翻页，
  已在首页时回首页禁用；列表长度变化后重新按真实页数判断。触屏与实体输入同一规则。
- 切页、切状态或进入实时对话后，正在按住的摇杆必须回中才重新接受方向，防止旧连发进入新页面。

## 按状态显示控件

### 蓄力输入（0.7.93，p4-motion-v1）

`input.hold: "jump.charge"` 声明一个按住/松开动作，必须绑定 SW1 短按，
且同时声明 `scene.motion`。按下调用该动作的 transition 与 `charge` 规则；
松开通过通用运动核心发射一次，不再补发普通短按。PC 触屏按钮与实体键共享同一语义。
触屏拖出按钮、pointercancel、失焦、暂停、切页、退出、换包均取消蓄力，不发射；
一次手势只有一个输入所有者，多指或另一输入源不能接管已有蓄力。
全局退出和实时对话绑定仍优先。该动作不得同时声明 press、repeat、confirm 或 cooldown。
0.7.94 修复了实体 SW1 被旧 `voice_ptt` 默认绑定阻挡的问题：在声明 hold 的组件内，
该次按住由组件完整接管，不启动旧 PTT；宠物页仍保留 PTT。其他明确的 hold 绑定仍优先。
被拒绝的蓄力（例如空中按住或触屏已占用）也吞掉该次短按，不在释放时补发蓄力。
空中按住不产生下一次跳跃队列。暂停不补演经过的时间。
详见 [motion.md](motion.md)；同步前必须核对实际设备 `widgetMotion`，
不能仅凭资源包通过离线校验推断设备已经具备能力。

应用图形节点可声明 `state_mask: 1..63`，位序对应 runtime.states 的索引，未设置表示全部状态。只能引用已声明状态，且 runtime 必须声明上述 input 能力。背景 JPEG 不可加状态过滤。

例如 states 为 `["ready","playing","result","paused"]` 时，操作键用 `state_mask: 2`，开始/重开/继续键用 `state_mask: 13`，暂停/继续键用 `state_mask: 10`。触屏命中与渲染使用同一过滤。

新输入包允许最多 24 条 transition；旧包仍为 12。变量 8、状态 6、页面 4、节点 32、runtime 紧凑 JSON 8191 字节等预算不变。不要通过重复按钮、文案或无效 transition 消耗预算。

## 宿主状态与确认

`host: true` 且使用 input v1 的应用，图形节点可声明 `host_mask: 1..255`。
位序为 ready(0)、active(1)、paused(2)、picker(3)、draft(4)、history(5)、
busy(6)、error/offline(7)。例如天气上一城/下一城只用 `host_mask:8`。
图片背景不可过滤；布局和哪些模式显示控件属于资源包，不硬编码组件 ID。

PC 服务快照提供有界 `ui:{mode,actions,context}`：actions 最多 16 个已声明宿主动作，
设备与 PC 都禁用当前不可用动作。等待回执显示 busy；10 秒没有有效回执显示离线，
不会把失败当成功。旧宿主无 ui 时保持兼容，不等于已验证新版交互。
context 为最多 64 个十六进制字符的显示内容版本，不是密钥。设备弹确认时捕获
该版本，确认后回传；笔记删除/转待办必须验证精确记录版本，不使用届时新选中的条目。
改选、改文案、退出或重复确认不能误删另一条记录。PC 的直接笔记列表仍按稳定 noteId
和明确确认操作，删除不影响已关联的待办。

新版输入包最多声明 16 个宿主动作（旧包仍为 8）；实体按键映射仍最多 8 个，
额外动作必须通过可达的触屏控件呈现。自然声景可声明 rain/sea/fire/insects
四个定点选择，保留 previous/next 与 up/down。选择静音状态下的声景不自动播放；
播放中选择同一声景不重启计时，换声景重新计时，退出即停止。

## 兼容游戏

仅维护现有旧预设时使用：

- 方块 `game.actions.soft_drop` 是可选动作；一次移动一格，触底不因该动作立即锁定并生成下一块。必须有物理方向绑定，可在 repeat 中声明。`drop` 仍为一次直落，不应连发。旋转保持 SW2。
- 贪吃蛇 `game.direction_mode: "absolute"` 时，actions 必须包含 start/left/right/up/down。一步只缓存一次有效转向，禁止 180° 掉头。不得把绝对方向误标为相对蛇头转向。
- 恢复暂停的 transition 不应重新启动游戏 C 核心；局面、分数和运动时钟保留，不补演暂停时间。

新游戏仍应使用通用 scene，不得把上述兼容预设作为新游戏的代替品。

## 媒体触屏

声明统一 input 且已有 `surface.input: "p4-media-touch-v1"` 的 PC 电台，列表行可直接点选；音量 meter 扩展为至少 40px 高的触屏命中区域，拖动释放后只提交一次绝对音量。列表操作核对来源和队列版本，过期触点不得误选另一首/台。没有列表数据或服务连接时，不虚构可用项。

## 验收

必须覆盖：快速点击、按住、回中再操作、触屏/实体键混用、状态切换后旧事件、确认/取消/超时、全局改键优先级、按钮显示与命中一致。保持 PC 预览、设备解释器、Python/Rust 校验和技能文档一致。真实声音、设备显示和 USB 链路仍需独立实机验收。
