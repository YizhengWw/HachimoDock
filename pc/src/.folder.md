# Host collection interaction

The offline framework UI fixtures include fixed host collection slots using
the production AppSurface. Replacing host context during a pointer gesture
cancels the old click; empty slots remain disabled. Synthetic browser replies
test rendering/input only; the actual composition request/state/storage path
is independently exercised by Rust contract tests.

Startup recovery: index.html retains a standalone loading view and public/startup-guard.js runs independently of React chunks. main.jsx dynamically imports App behind a root boundary. Only fixed failure category/type is logged; user-triggered reload never replays mutations. Native page-load logs only owned asset URL structure without query/fragment/private paths. This improves visibility, not proof of the prior WK blank-page root cause.
The mounted React Ready boundary also removes the loading overlay directly, so an unavailable independent guard cannot cover a working interface.
Component transfers use read-only device audio preflight and manual stop/recheck; never stop real-time voice automatically. Device removal preserves application saves only with the explicit peer capability; clearing needs explicit intent and confirmation and does not promise deletion of independent program snapshots.

Voice runtime polling now waits for a completed known USB target, binds asynchronous results to device/channel identity and uses native ASR exclusively for P4. Credential configuration is distinct from runtime running; stale legacy results cannot replace current UI state.

Native startup supervision additionally covers absent HTML: one managed worker waits for the main document generation/token handshake and one RootReady confirmation. A25s timeout presents an OS dialog with user-only reload/exit/dismiss; no automatic reload or mutation replay. Navigation invalidates late ready/notices/actions; at most one dialog remains outstanding. Permissions allow only the local main frontend commands. This is recovery visibility, not a diagnosis of the earlier WK failure.

Follow/appearance assignment is single-flight per provider and pins USB board, connection and boot. Each explicit request first performs one read-only reconciliation, then lets native verify content/cache metadata for its own fresh switch; local appearance IDs do not skip either gate. Matching USB binding submission precedes profile persistence. Unknown results are neither replayed nor presented as a confirmed old image; bridge-start partial failure remains visible.

One new follow click owns a fresh intent UUID and a distinct read-only observation UUID. usb_reconcile_appearance_unknown must prove quiescence of an old unresolved transfer, or report no pending journal entry, before this click may start its own native mutation. The old result stays unknown; mutation catches never reconcile/retry/resume it. Cancellation, lost ownership, changed USB generation or boot stop continuation. The UI briefly shows confirmation without a separate reconciliation button; missing firmware proof still prompts an upgrade. Native codes, boot IDs and pack IDs are not displayed.
