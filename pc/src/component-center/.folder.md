# Component center

- `ProgramBackground.jsx` and `program-background.js` expose the private native
  installed-program controller only after exact v2 boot binding + inspect-v1
  negotiation. One page owner, one read/mutation at a time, no automatic start,
  install, boot policy, permission grant or replay. Hidden/unmounted owners
  stop polling without stopping an intentionally running native program.
  Unknown mutations require explicit read reconciliation; stale stop buttons
  retain their exact observed boot/registration. Reported pending checkpoints
  are not disk durability. Default firmware creates no owner/IPC/panel.

- `component-program.js` and lazy `ProgramAppPreview.jsx` connect data-only
  component events, same-C timers/output transactions and private checkpoints to
  the actual component preview. One slice per turn; hidden/blurred instances
  stop, with explicit fresh reactivation only. Old components load no VM. This
  preview cannot grant device execution, services or arbitrary code. The device
  execution gate remains closed until P4 timing and commit/audio review.
  Full-queue controls expose backpressure from the actual native queue, not a
  second JS pending counter. Keyboard transient roles are exclusive writers.

- `host-collection.js` expands the opt-in PC-fed visible projection into standard
  AppSurface nodes. Empty/unavailable slots have no actions. ComponentAppPanel
  advances a local epoch on every distinct projection, including batched
  away/back updates; AppSurface cancels obsolete presses. It never loads full
  records into the device, creates variables per row or grants device execution.

- `device-json.js` and the mirrored skill module reject decoded NUL in
  device-bound JSON strings/keys before preview initialization. They preserve
  valid literals and input objects. `deviceJsonStringsValidText` also rejects
  unpaired UTF-16 in decoded values/keys; initialization uses that strict path.
  The old no-NUL helper keeps its scope. Neither helper is JSON grammar/schema,
  raw byte decoding or arbitrary object/cycle validation.
  `deviceJsonWithinDepth` independently caps decoded container paths at 32 before
  initialization; shared aliases cannot hide a deeper path, cycles cannot spin
  forever. It does not clamp/delete content or authorize a device capability.

- `program-core.js/.wasm` plus generated `program-bytes.mjs`: opt-in offline
  authoring library, reused only by the explicit candidate component route. The
  product C decoder and cooperative integer interpreter execute the same P4P1
  data images in preview; no component JS/WASM/native callback is accepted.
  A fixed 256 KiB instance cannot grow/import services. Queue pressure, unread
  reports, exact seed restore and latched cancellation retain native semantics.
  Components without program do not import it; no device PROGRAM/PERIPHERAL quota
  is granted by a preview.

- `form-v2-core.js/.wasm` and generated `form-v2-bytes.mjs` run the same pure C
  bounded mixed form editor as the candidate device, instantiated only for v2.
  `FormTextEditor.jsx` provides draft-only PC keyboard/IME input with stale-context
  rejection; it never commits on Enter or bypasses the device capability gate.
  Text budgets, cancel, navigation and persistence remain explicitly bounded.

- `form-v1-core.js/.wasm` and generated `form-v1-bytes.mjs` execute the existing
  device integer/choice editor for legacy previews, with fixed 64 KiB and no
  imports/growth. One native instance is cached per current declaration; every
  call reloads the entire typed integer snapshot. No form means no instance.
  Labels remain authored data, not another arithmetic/transition implementation.
- `app-form.js` routes the opt-in bounded integer/choice editor to shared C: separate
  draft and committed vars, atomic accept, cancel/hide/leave abandonment, and
  declared physical action bindings. `field_bind` resolves through existing
  text/button rendering; it adds no keyboard, dynamic list or host service.

- `app-navigation.js` adapts explicit local push/back/replace/reset through the
  same fixed C navigation core as the device, with a lazy 64 KiB zero-import
  WASM instance and complete per-call snapshots (no package code). It keeps eight
  parent pages and page-scoped actions; shared vectors match the firmware core.
  It does not execute package scripts or imply host form/service support.

- `collection-core.js/.wasm` is a fixed-memory, same-C keyed collection authoring
  model, not an enabled native control or package route. Replacements validate
  in fresh instances; hidden selected IDs and unbound source records survive.
  Shared vectors run in native C, WASM and the independent existing Rust service.
  The explicit cv_* export list excludes trusted native host/fast-path functions;
  raw authoring actions still validate fully, and status reads the committed view.

- `app-viewport.js` shares bounded content projection and clipped hit testing
  between preview and runtime tests; fixed navigation keeps screen coordinates.
  Shared C/Python/JS vectors cover offsets and clipped buttons.

- `side-core.js/.wasm` and `SideSceneLayer.jsx` preview the opt-in bounded
  tile-world profile using the same C core as firmware; no package scripts run.
  `side-core.test.js` guards types before WASM coercion and cross-copy parity.

- `runtime-semantics.test.js` consumes the same versioned vectors as the Python
  model. Omitted tick state conditions are global; state changes reset epochs.

- `library-order.js` merges local and builtin sources without deleting revisions.
  Exact build-owned content is marked `isBundledCopy` by the native hash registry
  and retains factory order; genuine user revisions retain recent-install order.
- The view reuses its last successful in-memory library snapshot across remounts;
  initial loading does not briefly render a different builtin-only order.
- `ComponentAppPanel.jsx` exposes news playback separately from generation state.
  Opening the PC preview must never itself start device audio.
- `app-viewport.js` shares independent-region projection and hit clipping with firmware/Python. Multi-region input is still explicit actions, not implicit per-region wheel routing.
- `ComponentAppPanel.jsx` uses unique event IDs and current host context for both composition v2 and durable v3 actions.
# Bounded canvas development path

`CanvasLayer.jsx` uses the product-owned `canvas-core.wasm` compiled from the
device's integer raster core. Declarations and scalar bindings are data only;
no component WASM, framebuffer pointers, audio or external requests are allowed.
No canvas declaration means the layer is not mounted/fetched. Snapshot absence,
type errors, page changes, async replacement and unmount never retain old plots.
The package's native capability gate and target hardware timing remain separate.

- `ServiceBridgeControls.jsx` is the PC panel for typed bridge commands and explicit
  local audio import. `ComponentAppPanel` supplies the current event/context owner,
  freshness, errors and pending state; the controls do not replace the device
  projection, image handles or command single-flight boundary.
