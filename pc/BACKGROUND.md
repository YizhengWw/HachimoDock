# 后台运行与菜单栏

在 macOS 和 Windows 托盘初始化成功时，关闭主窗口后，HachimiDock 会继续在后台运行，保留 USB 连接、状态同步和后台服务。

- 菜单栏图标提供“打开 HachimiDock”和“退出 HachimiDock”两个选项。
- 在 macOS 上，关闭窗口会隐藏 Dock 图标；从菜单栏打开窗口或再次启动应用时恢复主窗口和 Dock 图标。
- 关闭窗口不会中断传输、播放或未完成任务。真正退出时保留原有的任务和未保存修改确认，并清理后台服务。
- USB 退出确认仅跟踪需要保护的设备写入任务；等待读取配置、音量、媒体状态或组件清单时不会提示“正在写固件或资源”。这些查询仍与写入串行执行。固件 OTA、形象资源同步、组件安装/修复/删除、目录更新及配置设置在写入、等待回执和提交期间保留退出确认；任务完成或返回错误后释放保护。
- 显示器或缩放比例变化不会重新显示已隐藏的窗口。
- 托盘初始化失败不阻止主窗口打开；关闭窗口恢复原有退出确认与清理流程。Linux 当前也保留关闭退出行为，避免桌面不显示托盘时失去打开和退出入口。
- macOS 保留默认菜单，仅将其中的 Quit / Command-Q 接入应用退出确认；这不拦截系统强制退出或 Dock 的原生退出。

使用菜单栏的“退出 HachimiDock”或 macOS Command-Q 停止程序。此功能不包含开机自动启动或阻止系统休眠。

按照项目现有的桌面端构建流程构建；Tauri 已启用 `tray-icon` 特性。

## USB 退出保护回归

2026-11-06 修正了“共享传输锁占用 = 正在写固件或资源”的错误判断。
配置读取、组件清单、音量/媒体状态等只读请求也持有这把锁，等待读取回执时
可能弹出写入警告；锁中毒也会使旧判断持续为真。现在使用独立的写入任务计数，
作用域结束时自动释放，覆盖正常返回、错误和栈展开。串口互斥与原有的未保存修改、
实时对话、组件音频退出确认均保留。

形象同步在已有的串口/原生 USB 修改准入点开始保护；仅查询缓存、槽位或恢复证据
不构成写入。保护随该次 Attempt 的所有者释放，包间空隙和等待提交回执不会提前解除。
固件、组件资源及持久配置使用同一计数，结束一个嵌套任务不会清除其他任务的保护。

验证命令：

~~~sh
cd pc/src-tauri
cargo test --lib --locked exit_protection
~~~

8 项回归使用真实 USB 管理器和内存设备的延迟回执：只读配置/清单/媒体查询、
音量查询与设置、固件 begin/chunk/commit、组件安装成功/失败及删除、形象修改、
嵌套任务、异常释放和锁中毒。只读配置用例在旧代码上稳定失败，修正后通过。
这些测试不向物理设备刷写固件或资源。
