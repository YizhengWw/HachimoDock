# 城市电台：实现选择与验收

## 选择（2026-10-15）

当前目标是跨平台 PC + USB 播放，不是另一套独立 Wi-Fi 固件。继续使用 Radio Browser 作为公共目录，由双端声明式 PetUI 包定义搜索映射、面板和设备布局；宿主提供安全联网、解码、缓冲、USB 和隔离存储。未复制以下播放器项目的实现代码。

| 项目 | 适合借鉴的部分 | 本项目取舍 |
| --- | --- | --- |
| [Radio Browser](https://api.radio-browser.info/) | 公共电台目录、UUID、DNS 服务发现 | 采用目录；包使用 all.api.radio-browser.info，不固定某一地区节点。连接使用经过安全校验的 DNS 地址，不承诺目录中的每个源都可用。 |
| [Shortwave](https://apps.gnome.org/Shortwave/) | 搜索、个人收藏、小屏交互 | 参考交互设计；不是可直接装入 PetUI 的资源包，不引入 GNOME 桌面运行时。 |
| [RadioDroid](https://github.com/segler-alex/RadioDroid) | 基于同一目录的移动端收听流程 | Android / GPL-3.0；不移植整个 Android 应用。 |
| [PyRadio](https://github.com/coderholic/pyradio) | 跨平台电台和播放列表管理 | MIT；依赖 Python 与外部播放器。可研究恢复策略，不为 USB 输出另引入第二套播放器栈。 |
| [yoRadio](https://github.com/e2002/yoradio) | 嵌入式收音机、实体按键、网络状态 | GPL-3.0，面向 ESP32-audioI2S/VS1053；后续独立联网设备可参考，不直接替换 P4/PetUI 固件。 |
| [ESP32Radio-V2](https://github.com/Edzelf/ESP32Radio-V2) | 嵌入式广播、I2S/SPDIF 与播放列表 | 主仓库 Apache-2.0；硬件、运行时不同，不能据此宣称已适配 P4。依赖授权需另核对。 |
| [8DE4732A/fm](https://github.com/8DE4732A/fm) | 国内省市分类、搜索页面 | 其 README 描述依赖蜻蜓 FM API、签名流与 Worker；未见其证明可向本产品转授音源使用权，不采用这些接口或签名机制。 |

“最好”在这里是适合现有硬件、能实测播放、维护边界清晰，并非星标最多。目录及播放器的软件许可不等于广播内容的使用授权；本组件不录制、下载或再托管广播，也不宣称所有音源都无版权风险。

## 修复机制

- 校验通过的已安装组件默认启用，首次使用与更新不再要求授权确认；打开详情或设备组件即可加载目录。手动停用仍停止服务并保留收藏，更新不自动重新开启；默认启用不代表自动播放或跳过网络安全校验。
- 搜索结果直接播放，不强制收藏；收藏最多 20 个，历史最多 10 个，保留于本机，不装进组件包。
- 系统 DNS 返回代理 fake-IP 时，不能直接将 198.18/15 加入公网白名单。通过 HTTPS 公共 DNS 取得真实地址，继续校验并钉住 IP。优先阿里公共 DNS，网络失败后尝试 Cloudflare；面板披露服务方，只发送域名，无用户对话、搜索词、凭据或 ECS 子网参数。
- DNS 结果与 HTTP 连接均有数量/时间上限；私网、凭据 URL、非标准端口与越权跳转拒绝。不会绕过 TLS 校验。
- HLS 复用钉住地址的 HTTPS 连接，避免每个小片段新建 TLS；PC 解码队列为 32 个 80 ms 帧，启动预缓冲 16 帧。音频仅在内存中流转，解码器只读取管道，不可自行联网。
- macOS 播放专用线程复用实时语音已有的 AudioActivity/QoS 保护，防止 250 微秒的串口分片等待被系统合并成毫秒级等待；保护随播放线程退出释放，不阻止系统或屏幕休眠。增加缓冲本身不能修复发送速率低于播放速率的问题。
- 设备 media/status 与 audio/* 一样走带锁的完整帧排队发送，不在 JSON 正文与换行之间等待 TX 完成。旧路径实测每包写入约 14 ms、回执合计约 106 ms，而音频包仅有 80 ms，持续播放必然欠载。此修复在基础固件，不应通过放宽测试门槛掩盖。
- 未启用、空收藏、网络失败不再静默丢弃。新增 source 隔离的 media/notice，在支持它的固件上显示原因；不停止其他音频、不延长媒体租约。

## 验收命令与边界

### 设备选台（组件 1.1.0）

- PC 声明式搜索新增可选 `browseQuery`（1–30 字）。服务默认启用，打开组件后请求该目录；手动停用后不请求、不自动播放。城市电台用“广播”查询最多 20 个真实电台，不在固件或包内写入直播地址。
- 目录缓存与个人收藏分离，设备队列为收藏优先、目录补齐、按 ID 去重、最多 20 条。重启保留缓存而不恢复播放；旧版 library.json 自动兼容。
- SW2 打开/返回列表，上下循环选择，中键或 SW1 确认；主画面左右切台、上下调音量、SW1 播放/停止。退出仍服从全局设置。
- 加载失败可重新打开设备列表重试，15 秒限流；网络请求不持有操作锁，撤销后迟到结果不会写入或下发。空列表是等待态而不是播放失败。
- 暖白/墨色/橙色布局由原组件资源包声明，列表反色圆角选中态是通用 surface 渲染能力。不增加组件脚本或外部代码。
- 此迭代的 UI 模拟和协议测试不代替新客户端、新固件的实际安装与听感验收。

常规：前端测试/构建，Rust media_dns/media_network/component_media/component_extension 测试，固件 p4_media_runtime_test.py 和 petui_media_surface_test.py，PetUI 校验、自测与原子发布。

`media_network::tests::live_hls_decode` 是显式忽略的公网集成测试：搜索真实电台，读取 HLS，检查解码 PCM 非静音，不保存音频、不使用设备。

`component_media::tests::live_usb_radio` 是显式忽略的真机测试：需用户同意、客户端断开、设置 RADIO_TEST_PORT，独占串口短暂播放广播，检查持续 playing 状态并停止，使用临时本地数据。不会刷机。该测试不可在普通 CI 自动运行；状态回执不能代替用户对音质的听感确认。

模拟预览只验证启用、搜索、播放、停止等 UI 状态，不联网、不写入授权、不证明真机出声。Windows 编译通过也不能代替 Windows 实机播放测试。
