# 精细游戏画面层与旅行明信片

## 机制与边界

- 保留 `snake-turn`、`block-combo`、`flappy-bird` 的 ID、名称、规则、速度和物理键；不是换名的新游戏。
- 贪吃蛇：开始、相对左右转向、吃食物增长、碰撞结束、重开。森林纸感底图、圆润蛇身、苹果与清晰侧栏。
- 方块：开始、左右移动、旋转、快速落下、消行得分、堆满结束、重开。深靛背景、立体圆角方块和独立操作区。
- 飞鸟：拍翅开始/上升、自动下落、穿过障碍得分、碰撞结束、重开。低对比天空底图、鸟的身体/翅膀/眼睛与管道层次。
- 玩法由已有固件 C 核心执行；PC 预览编译同一 C 核心为受信任、无导入、256 KiB 有界 WASM。组件内不携带代码。
- 触屏按钮与实体键引用同一 action；全局退出优先。画面背景不承载虚假控件，不增加任意手势。
- 旅行补四张默认目的地明信片：海岸、森林、山丘、星光小镇。可以先欣赏图画和文案；真实到达才增加次数与“已带回”记录。新包不覆盖已有旅行进度。

## 契约

`surface.game_view={engine:"p4-game-surface-v1",x,y,w,h}` 需要
`widgetGameSurface=p4-game-surface-v1`，依赖原有 App Surface/Graphics/Images，
字形需要 Typography。当前只支持维护已有 `game.type=snake|blocks|flappy`，
不与 host/scene/media/data/instrument 混用，不能据此创建任意新游戏。
视口位于 640×480 内，宽高至少 64；实际设计需保证单格至少 8 px。
底图和静态面板缓存一次，游戏绘制在静态层之后、文字和按钮之前；
画面内容必须来自实时游戏帧。图形扩展仍受 8191 字节 JSON、
4 张图片、128 KiB 编译图片总量限制。

构建预览核心：`CLANG=<支持 wasm32 的 clang> node pc/scripts/build-classic-runtime.mjs`。
无兼容固件时拒绝同步新游戏包，不静默降级成旧画面。
原生导入、同源玩法测试不等于实机验收；升级设备前仍需用户授权。

内置资源使用 PC 编码器生成的 P4I1/P4J1，缓存在
`firmware/assets/builtin-surfaces/<id>`，与 PNG、声明和编码结果的 SHA-256
绑定。构建与出厂工具拒绝过期缓存，不需要在 CI 中另实现 JPEG 编码器。
用户旅行记录、密钥和本机绝对路径不进入缓存。

高清资源只保存在资源包和出厂存储中，不重复嵌入两个 OTA 应用槽。
OTA 内置包使用有界 zlib 压缩的无图片启动布局（保留规则和控件），仅在
该组件尚未安装时使用；已经安装的完整包不会被启动布局覆盖。
完整画面需由客户端同步新版同 ID 资源包；只刷固件不等于更新资源包。
