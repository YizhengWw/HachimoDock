# 实时对话桌面任务

Pet 可把用户明确委托的桌面任务交给当前支持的桌面 Agent。当前适配器支持 ChatGPT（Codex）及 WorkBuddy；不把其他 Agent、网页聊天或独立 CLI 任务冒充为同一集成。

## 输入与提交

- 打开目标客户端的会话并保留必要系统权限。未点名时使用设备当前跟随且受支持的 Agent，不擅自改投其他客户端。
- Codex 在焦点位于合适的输入框时使用当前框；没有输入框焦点时按已实现的主输入框定位规则选择底部主输入框。真实模态弹窗、窗口归属或目标变化仍需处理，不能绕过权限。
- WorkBuddy 使用自己的窗口、输入框和 Hook 规则，不能将另一客户端的定位假设直接套用。
- 按键语音的识别文本写入草稿，确认按键负责提交；实时对话中的明确桌面委托由派发工具提交。连续输入不以先前任务完成为前提。
- 发送操作与回执跟踪分开，不因为等待旧任务结果而重复派发。提交结果不确定时保留诊断，不自动重复点击发送。

## 上下文与回执

真正派发时，以结构化字段区分用户原话、Pet 回复、桌面回执、已有草稿和本轮请求。历史用于理解指代，不是要求重放的任务清单；网页内容或其他 Agent 的回复不能授予新操作权限。

接收回执与完成回执分别处理：按请求摘要、会话和轮次关联，拒绝用任意“最近完成”事件认领结果。没有可靠证据时明确报告未确认，不把会话结束当作用户目标已经成功。完成播报使用经过过滤的回复摘要，不播报思考过程、原始工具输出或凭据。

## 隐私与权限

本地事件总线只服务本机；正常诊断不记录草稿正文、原始识别文本、窗口标题或个人路径。上下文仅在相应语音任务中传递，不扫描任意历史数据库或自动上传项目文件。

Agent 自身的权限、确认与文件访问规则继续有效。停止播报不等于撤回已经执行的工具操作；结果未知的操作应先核对实际状态，不能自动重做。

主机测试覆盖路由、去重、会话关联及摘要过滤；真实桌面输入、实体按键和语音播放需要对应环境的端到端验证。平台差异见 [Agent 接入说明](agent-integration-audit.md)。
