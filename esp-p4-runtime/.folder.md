# Folder Plan: esp-p4-runtime

## Architecture
- 2026-08-06 firmware `0.7.37-p4` OTA clock fix: the inactivity reaper now
  rejects a main-loop timestamp captured before a just-completed chunk, avoiding
  unsigned underflow that previously cleared a healthy transaction and made the
  following chunk report `firmware transferId mismatch`. Protocol schema 6
  advertises that the race is fixed so future desktop updates can restore the
  full 4092-byte chunk size.
- 2026-08-06 firmware `0.7.36-p4` interrupted-transfer recovery: firmware
  status echoes the optional query request id and exposes the active OTA id so
  Pet Manager can abort the exact transaction left by an unplugged host before
  restarting. Firmware and appearance writes now display a lightweight
  animated transfer page that avoids asset decoding while flash content is
  changing, replacing the former frozen last frame.
- 2026-08-06 CH343 raw-appearance host contract: the cross-module protocol
  suite now requires Pet Manager to pace both firmware JSON and 8 KiB raw
  appearance bodies through shared 64-byte flushed writes at 4 Mbaud. The
  official standalone test list also tracks the renamed global-exit built-in
  check again; this desktop-side fix does not change the firmware image.
- 2026-08-06 firmware `0.7.35-p4` appearance-transfer recovery: serial JSON/raw
  and native-USB transfers refresh an activity deadline while bytes arrive.
  Fifteen seconds without activity aborts incomplete slot-1 staging, resets raw
  state, releases `asset_transfer_active`, and resumes rendering without
  changing the previously active appearance. The paired desktop still aborts
  immediately on every host-side error; the device timeout is the crash and
  disconnect fallback.
- 2026-08-06 firmware `0.7.34-p4` OTA transport package: the desktop now uses
  the board-advertised 4 KiB decoded receiver at 4092-byte padding-free chunks,
  retries transient Base64 corruption at the current size before falling back,
  and automatically restores larger chunks after a stable success streak.
  Begin-ACK delivery failures are retried within one click. The application
  image version advances so a `0.7.33-p4` device can exercise this corrected
  host path through the bundled updater; components and persisted data remain
  unchanged by the transport-only release.
- 2026-08-06 firmware `0.7.33-p4` component-navigation isolation: a running
  component still gives its mapped gameplay action priority after the current
  global `page_back` gesture, but every other unmapped system-navigation
  binding is emitted as disabled. SW2 may therefore remain the normal global
  Component Center shortcut without acting as a second component exit.
- 2026-08-05 firmware `0.7.32-p4` first-frame boot gating: app entry drives the
  LCD backlight inactive before SPIFFS and built-in component migration. Panel
  initialization keeps it hidden, and only a successfully rendered complete
  frame reveals it. A normal OTA software restart therefore no longer exposes
  the panel controller's blue reset surface while built-ins are refreshed.
- 2026-08-05 firmware `0.7.31-p4` global component exit and OTA component
  bundle: while `app` is open,
  the current persisted `page_back` event is resolved before any component
  action, including joystick directions. Package-authored navigation actions
  are ignored for legacy compatibility, leaving SW1 short as the default exit
  and SW1 long PTT unchanged. Factory components omit navigation bindings and
  use SW3 for their primary/start actions. The A/B application image embeds
  those seven packages; a build-id marker triggers transactional same-id
  replacement after OTA, removes retired Falling Catch, restores the previous
  active component when possible, and leaves unrelated user packages intact.
- 2026-08-05 portable component lock: local ESP-IDF override entries resolve
  through `PET_P4_PROJECT_DIR`, which PlatformIO exports before CMake starts.
  macOS and Windows builds can now share one tracked lock file without
  requiring the registry; a post-build action normalizes ESP-IDF's generated
  absolute paths back to the portable token so the worktree remains clean.
- 2026-08-05 input-config v7 defaults: firmware `0.7.29-p4` maps SW1 short to
  `page_back` and SW3 short to `page_enter`, matching the desktop defaults.
  Version-6 NVS migration swaps only bindings that still match the former
  shipped values, preserving custom mappings. The on-device Component Center
  footer now reads `SW1返回，SW3进入`. The same validated application image is
  bundled with the PC release for older-only sidebar upgrades.
- 2026-08-04 input-config v6 defaults: firmware `0.7.28-p4` migrates only the

- 2026-08-04 historical factory input layout (superseded 2026-08-05): the

- 2026-08-04 joystick travel reliability: firmware `0.7.27-p4` derives

  longer leaves right/up/down below one fixed delta. All four directions move
  the on-device component catalog, while component-local mappings and the

  live center/current/min/max ADC values for hardware verification, and host

- 2026-08-04 four-direction joystick compatibility: firmware `0.7.26-p4`
  samples JOYSTICK_X/GPIO21 and JOYSTICK_Y/GPIO20 through ADC1, calibrates the

  hysteresis plus bounded held-direction repeat. GPIO4 remains the center key.
  Up/down use `joystick.up`/`joystick.down`; left/right and center deliberately
  retain `knob.rotate_ccw`/`knob.rotate_cw` and `button.encoder.*`, so installed

  sampling also remains active for old boards. Input config advances to v5 and
  wire protocol schema to 5; host decoder tests and a complete ESP-IDF build
  cover the new path.
- 2026-08-04 reproducible factory-build repair: factory provisioning resolves

  normal CMake builds continue to inject the real firmware build id, Git SHA,

- Scope: esp-p4-runtime
- Function: ESP-IDF firmware for the ESP32-P4 480x640 desk-pet device. Owns the landscape 640x480 render model, ST7701S display, GT911 gestures, protected-slot H.264/WAV assets with legacy MJPEG compatibility, USB JSON/native bulk protocols, configurable GPIO controls, the shared bounded game/tool runtime with optional generic grid scenes, ES7210-preferred capture with ES8311 ADC/DAC fallback, screenshots, live stats, and rollback-capable A/B firmware updates.
- Display transport: WLK2802 uses a one-lane, 800Mbps write-only ST7701S command link. Startup skips the optional panel ID read and disables DSI command ACK requests before sending the vendor table, preventing an unreturned ACK from filling the command FIFO and blocking backlight initialization.
- Display reset: the local ST7701S override waits 120ms after releasing RESX before panel initialization, matching datasheet section 7.5.5 and making a fully cold panel deterministic.
- Sync: if this folder changes, update this file immediately. UART0 logs and JSON protocol writes share the transport mutex so high-baud CH343 traffic cannot splice log text into protocol frames; a two-second PC heartbeat drives the compact, content-width-aware top-right P4 waiting/initializing/disconnected capsule with a six-second timeout. The capsule stays to the right of the main-page indicator and replaces the app state pill while visible. OTA also serializes USB/UART handlers, validates sustained runtime health, and recovers timed-out transfers. The display exposes `main`, the on-device `components` catalog, and the active mini-app `app`; the former fixed stats page is removed while its bounded data model continues feeding widgets such as Token 消耗. Touch swipes retain the fast main/app toggle, while physical inputs provide hierarchical catalog navigation. The input contract exposes ten PC-configurable logical gestures and serializes them into fourteen internal bindings; switch and encoder long-press rows use mutually exclusive `.long_press` one-shot and hidden `.hold` bindings, with SW1 long as the default PTT owner. Component-declared physical inputs are resolved before the persisted global map only while `app` is open; outside the component, the configurable `page_enter`/`page_back` defaults and other device-page actions stay authoritative. Live conversations arrive on `session/current`; each queue item retains its session id, title, latest progress content, and state, while `speech/text` updates the matching item by session id. The main page renders up to three fixed 556x120 cards with a one-line title, a two-line UTF-8-safe 1.5x MiSans progress preview, shared animated status markers, and selected-row PTT waveform; Agent `speaking` events reuse the `working` spinner instead of displaying a voice-like equalizer, while actual user PTT keeps its independent waveform and microphone. The selected card uses a four-pixel green outline, wider left rail, and pale green surface while unselected cards stay pure white. Existing cards remain visible through brief heartbeat or asset-sync transitions, and an active lifecycle fallback uses the same selected-card geometry during the short post-boot queue-sync window instead of switching to a separate large bubble. The compact idle bubble remains intentionally compact. Text inside bounded UI components is vertically aligned from each rendered glyph's actual LVGL box and baseline metrics instead of hard-coded origins. The embedded full-CJK UI font is MiSans Medium 16px at 1bpp, with the source OTF excluded under Xiaomi's license. The mini-app page keeps the classic dark information layout for normal widgets and uses matched bright pixel panels, palettes and built-in sprites when `visualStyle=pixel`. Hardware validation on 2026-07-16 confirmed ES8311 fallback capture over COM10 and fixed the Base64 frame buffer boundary.
- Page indicator: `main`, `components`, and `app` render the three-dot indicator at the same top-center coordinates; the app title is width-bounded before the indicator so long labels cannot overlap it.
- Reuse: `main/pet_p4_protocol.c` routes the shared message envelope; feature modules own bounded state and hardware behavior. `ref/src-tauri/src/usb_serial.rs` is the desktop counterpart for USB transfers.
